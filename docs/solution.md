## 0. Executive Summary

**The answer to the question as posed is yes — and it is stronger than hypothesized.**
The affine monoid generated by the nine ITCH 5.0 message types does not merely admit a
fast composition schedule: it *collapses*. Every sequential dependency in the state chain

```
S_k = A_k S_{k-1} + B_k ,      S = (bid_vol, ask_vol, last_px) ∈ ℤ³
```

is inessential. The net transformation of an arbitrarily interleaved batch of K messages
is exactly representable by a **commutative** monoid element, and the fold becomes an
order-free reduction — which is precisely the form that SIMD and multi-core evaluation
consumes with zero correction or synchronization.

**The three headline formulas.** For any batch B of *resolved* messages (Definition 2.1)
applied to one stock locate:

```
  A_net(B) ∈ { I₃, D₀ }              D₀ = diag(1,1,0)
                                      (D₀  ⇔  at least one price-setting message in B)

  B_net(B) = ( Δb, Δa, ε·p* )        Δb, Δa : plain integer sums, order-free
                                      (p*, s*) : the price setter with maximum stream
                                      sequence number (ε = 0 ⇒ no setter)

  Batch composition:  (Δb, Δa, p*, s*) ⊕ (Δb′, Δa′, p*′, s*′)
                       = (Δb+Δb′, Δa+Δa′, price of max(s*, s*′))          — O(1)
```

The product of K matrices `A_K⋯A₁` — the object your `B_net = Σᵢ (Πⱼ Aⱼ) Bᵢ` formula
suggests must be computed K times — degenerates to **a single OR bit**, because the only
matrices that ever occur are `I₃` and the idempotent `D₀` with `D₀² = D₀`. The K-term
weighted sum degenerates to **two integer accumulations and one tagged maximum**. There is
nothing left to vectorize *around*: the fold is a reduction, not a chain.

**What this is worth on the stated hardware** (2 Zen 5 cores @ 2.6 GHz; full derivation in §6.5 and §8):

| Quantity | Sequential fold (today) | Collapsed fold (this solution) |
|---|---|---|
| Sequential dependencies per 512-msg chunk | 511 | **0** |
| `A_net` computation for 500k messages | 500k matrix products | **1 OR bit per chunk** |
| `B_net` computation | 500k weighted mat-vec terms | **2 sums + 1 argmax per chunk** |
| Fold arithmetic, first pass over 500k msgs | ≈ 1,200 ms (measured) | **≈ 0.05 – 0.5 ms** |
| Fold arithmetic, *memoized replay* of the same 500k msgs | ≈ 1,200 ms | **≈ 0.01 – 0.05 ms** |
| Chunk-map composition cost | n/a (sequential) | **2× i64 add + 1 cmp/select** |
| Chunk signature storage | n/a | 32 B per chunk ⇒ 31 KB per 500k msgs (L1/SRAM-resident) |

Two consequences deserve emphasis because they change the architecture, not just the constants:

1. **The fold leaves the critical path entirely.** Post-collapse, the arithmetic cost of the
   book-state fold is ~0.002–0.006 cycles per message in vectorized form. At that point the
   pass is bounded by byte decode and order-cache probes (§5, §8) — the fold never again
   appears in a profile.
2. **Verdict replay becomes a table read.** Chunk signatures `(Δb, Δa, p*, s*)` are pure
   functions of (chunk bytes, cache state at chunk entry). In a replay engine that re-evaluates
   the same stream, signatures are computed once and *memoized*; every subsequent pass over
   500k messages is ≈ 976 `⊕` combines — literally the "976 operations instead of 500,000"
   target, and bit-exact by Theorem 8, not approximately.

**On the two hypotheses posed.**

- *Hypothesis 1 (sparsity / commutativity for disjoint locates).* **True, and understated.**
  Theorem 3 proves commutation for disjoint support, but Theorem 2 proves something stronger:
  once per-message deltas are resolved, **all** messages in a batch commute as book-state
  operators — same locate or not, interleaved or not. Disjointness is sufficient but not
  necessary.
- *Hypothesis 2 (pre-computed generator algebra for 256/512-msg batches).* **Exists, but not
  as a lookup table.** A finite composition table over exact ℤ³ maps cannot exist
  (cardinality argument, Appendix C — the generator set is infinite because quantities and
  prices range over 2³² values). The correct object is *better than a table*: the batch
  algebra `𝒜₅.₀ ≅ (ℤ², +) × (ℙ ∪ {⊥}, ⊔_seq)` is commutative and **freely generated by
  per-message signatures**, so composition is closed-form arithmetic (2 adds + 1 tagged max)
  with zero collisions, zero quantization error, and zero memory traffic. Memoized chunk
  signatures (§6.3) supply the "lookup" behavior where replay workloads want it.

**The honest caveat, stated up front.** The `A_k`/`B_k` of `E/C/X/D/U` messages are not
constants — they are functions of the order-ID cache (side, remaining quantity, resting
price of the referenced order). That dependency, not the ℤ³ arithmetic, is the true
sequential residue of the problem. §5 gives its exact structure (per-order-ID chains,
Theorem 7) and a two-phase evaluation algorithm that resolves it with a rare, bounded,
sequential fallback. And §8 gives the roofline: on 165 GB/s and 2.6 GHz × 2 cores,
15 B msg/s is reachable only in the *L2-resident decoded-token replay* regime — which is
exactly the regime this algebra enables, and in which the fold's contribution is
indistinguishable from zero.

## 1. Model, Notation, and the Question

### 1.1 State and messages

For each **stock locate** ℓ the maintained state is the integer vector

```
  S_ℓ = ( b_ℓ , a_ℓ , p_ℓ ) ∈ ℤ³
```

with `b_ℓ` = displayed bid volume (shares), `a_ℓ` = displayed ask volume, `p_ℓ` = last
trade price in integer ticks (ITCH 5.0 prices are 4-byte fixed-point, 10⁻⁴ implied
decimals; everything in this document is integer arithmetic — **no floating point appears
anywhere in the fold**, which is a precondition for bit-exact replay, §7).

The global state is the product `X = ( ×_ℓ S_ℓ ) × O` where `O = { order-id → (ℓ, side,
remaining, px) }` is the order-ID cache maintained by the engine. `O` is itself factored
per order-ID; this factorization is what Theorem 7 exploits.

Each of the nine message types induces an **affine map** on the locate it references:

```
  T_i : S ↦ A_i S + B_i ,      A_i ∈ ℤ^{3×3},  B_i ∈ ℤ³
```

A batch of K consecutive messages for one locate applies `T_batch = T_K ∘ T_{K-1} ∘ ⋯ ∘ T₁`
(rightmost applied first).

### 1.2 The composition formulas, verified

The problem statement's closed form is correct; we fix it as a lemma so the rest of the
document can cite it without re-derivation. Write each `T_i` as the pair `(A_i, B_i)`.

**Lemma 0 (batch composition).**

```
  T_batch(S) = A_net S + B_net

  A_net = A_K A_{K-1} ⋯ A_1                                  (rightmost = first applied)

  B_net = Σ_{i=1..K}  ( A_K ⋯ A_{i+1} ) B_i                  (empty product = I₃)
```

*Proof.* Induction on K. K = 1 is trivial. For the step, write `T_batch = T_K ∘ T′` where
`T′ = T_{K-1}∘⋯∘T₁ = (A′, B′)`. Then
`T_K(T′(S)) = A_K(A′S + B′) + B_K = (A_K A′)S + (A_K B′ + B_K)`, which is the claimed form
with `A_net = A_K A′` and `B_net = A_K B′ + B_K`; expanding `B′` by the inductive hypothesis
gives exactly `Σᵢ (A_K⋯A_{i+1}) Bᵢ`. ∎

Equivalently, each `(A, B)` embeds as an augmented 4×4 matrix

```
        ⎡ A  B ⎤          ⎡ A₂  B₂ ⎤ ⎡ A₁  B₁ ⎤   ⎡ A₂A₁  A₂B₁+B₂ ⎤
  M =   ⎣ 0  1 ⎦    ,     ⎣  0   1  ⎦ ⎣  0   1  ⎦ = ⎣  0       1    ⎦
```

so batch composition *is* matrix multiplication and is associative — chunking is exact for
any chunk size, before any structure is exploited. The invertible elements form the affine
group `Aff(ℤ³) = GL₃(ℤ) ⋉ ℤ³` with the semidirect product `(A₁,B₁)(A₂,B₂) = (A₁A₂, A₁B₂+B₁)`;
the ITCH generators are *not* invertible (`D₀` is singular), so we work in the monoid
throughout. This is harmless: monoid composition is still associative, and associativity
is the only property chunking needs.

### 1.3 The question, decomposed

The engineering question — *can 500,000 sequential affine updates become ~976 O(1) steps?* —
splits into three sub-questions of strictly decreasing algebraic difficulty:

- **Q1 (this section, §2–§4):** What is the structure of the monoid generated by the nine
  message maps, and does it admit an O(1), exact, order-free batch composition?
  **Answer: it collapses to a commutative monoid of rank 3 (§3, Theorem 2).**
- **Q2 (§5):** The `A_i, B_i` of `E/C/X/D/U` are functions of the order-ID cache, so the
  *inputs* of the fold are produced by a second fold over `O`. What is the exact parallel
  structure of that inner fold? **Answer: per-order-ID chains of expected O(1) length,
  fully commutative across IDs (Theorem 7).**
- **Q3 (§6):** How is the collapsed fold scheduled on 2 Zen 5 cores / 4 vCPUs so that the
  result is bit-identical to the sequential oracle under all 94 hydra.rs cells?
  **Answer: commutative monoid ⇒ any partition, any merge order, one tie-break rule
  (§4), zero locks on the hot path (§6.4).**

Everything is integer-exact. There is no approximation stage anywhere in this document:
every theorem asserts *equality*, and the performance claims follow from removing
arithmetic, not from tolerating error.

## 2. The ITCH 5.0 Generator Set

### 2.1 Resolved messages

The nine types split into two classes:

- **Self-contained** (`A`, `F`, `P`, `Q`): the volume/price effect is a function of message
  fields alone.
- **Cache-dependent** (`E`, `C`, `X`, `D`, `U`): the effect references a resting order by
  Order Reference Number; its side, remaining quantity, and (for `E`) resting price are read
  from the order-ID cache.

**Definition 2.1 (resolved message).** A message is *resolved* when its affine pair
`(A_i, B_i)` has been fully determined — i.e., for cache-dependent types, after the
referenced order's `(side, remaining, px)` have been looked up. Theorems 1–3 operate on
resolved messages; §5 handles resolution itself.

Notation: for side `s ∈ {BUY, SELL}` and integer `x`, let

```
  ν(s, x) = (x, 0, 0)   if s = BUY        (x added to the bid-volume coordinate)
  ν(s, x) = (0, x, 0)   if s = SELL       (x added to the ask-volume coordinate)
```

and let `I₃ = diag(1,1,1)` and `D₀ = diag(1,1,0)`. A price-setting message with price `π`
(in ticks) contributes the map `S ↦ D₀S + (v_b, v_a, π)`: volumes shift by the translation,
and the price coordinate is *assigned* `π` (the 0 on `D₀`'s diagonal annihilates the prior
`p`, which is exactly the semantics of a trade print).

### 2.2 The generator table

Policy defaults (each is a single engine configuration bit; the algebra is identical under
either choice — see Theorem 5 for the extension machinery):

- `E_SETS_LAST ∈ {order_px, no}` — whether an `E` execution prints `last_px` at the
  resting order's limit price (Nasdaq-consistent default: **yes**).
- `C_SETS_LAST` — only if the `printable` flag is set (default: **yes, flag-gated**).
- `Q_VOLUME_POLICY ∈ {print_only, clear_matched}` — default **print_only**; the cross
  consumes displayed liquidity that the feed reports through the ordinary `E/D` traffic.

### 2.3 The three structural facts

Everything in §3 flows from three properties shared by **all nine** generators:

```
(F1)  A_i ∈ { I₃, D₀ } ⊂ 𝒟 ,   𝒟 := { diag(σ) : σ ∈ {0,1}³ }   (0/1 diagonal matrices)

(F2)  (σ_i)_b = (σ_i)_a = 1  for all i
      — no generator ever scales or zeroes a *volume* coordinate.

(F3)  no generator ever *adds* to the price coordinate:
      a price update always has σ_p = 0 (assignment), never σ_p = 1 with B_p ≠ 0.
```

(F1) says the matrix part of the entire problem lives in an 8-element commutative
idempotent monoid — and (F2) restricts the ITCH-relevant part to **two** elements. (F3)
says price updates form a pure last-write-wins chain, never an accumulation. These are not
engineering assumptions; they are properties of the ITCH 5.0 protocol semantics (volume
changes are always absolute share counts, prices are always assignments), and they are
assertable at decode time as invariants (§9, step 3).

## 3. Structure Theorems: The Collapse of the Fold Algebra

### 3.1 Lemma 1 — the diagonal monoid 𝒟

**Lemma 1.** Let `𝒟 := { diag(σ) : σ ∈ {0,1}³ }`. Then:

(a) 𝒟 is closed under multiplication, and `diag(σ) · diag(τ) = diag(σ ∧ τ)`, where `∧` is
    pointwise logical AND;
(b) 𝒟 is **commutative** and **idempotent**: `diag(σ)² = diag(σ)`;
(c) `diag(1,1,1) = I₃` is the identity; `σ ↦ diag(σ)` is a monoid isomorphism
    `({0,1}³, ∧) → 𝒟`.

*Proof.* Diagonal matrices multiply entrywise: `(diag(σ)·diag(τ))_{cc} = σ_c·τ_c`, and on
{0,1} integer multiplication *is* logical AND. (b) follows from `σ ∧ σ = σ`; commutativity
from `σ ∧ τ = τ ∧ σ`. (c) is immediate. ∎

𝒟 has exactly 8 elements, and by (F2) ITCH 5.0 ever touches two of them: `I₃` and `D₀`.
The entire "matrix part" of the problem is therefore a two-element Boolean lattice — this
is the structural fact that the rest of §3 harvests.

### 3.2 Theorem 1 — the K-fold matrix product is one NOR bit

**Theorem 1 (product collapse).** Let `A₁, …, A_K` be the matrix parts of resolved ITCH
messages (§2.1), with `bᵢ := [message i sets price]`. Then

```
  A_net = A_K ⋯ A₁ = diag(1, 1, ε),      ε = (σ₁)_p ∧ ⋯ ∧ (σ_K)_p = ¬(b₁ ∨ ⋯ ∨ b_K)
```

In particular `A_net ∈ {I₃, D₀}`, and `A_net = D₀  ⇔  at least one message in the batch
is price-setting`. Moreover `D₀^m = D₀` for every `m ≥ 1`: the product is idempotent —
duplicating price-setters never changes it.

*Proof.* Each `Aᵢ ∈ 𝒟` by (F1), so by Lemma 1(a) the product equals `diag(σ₁ ∧ ⋯ ∧ σ_K)`
— the order of the factors is already irrelevant. By (F2) every volume bit is 1, so the
volume entries of the AND are 1. The price entry is 0 exactly when some factor has price
bit 0, i.e. when some `bᵢ = 1`. Idempotence is Lemma 1(b). ∎

So the 500,000-fold matrix product — which the naive reading of `A_net = Π Aᵢ` suggests
costs 499,999 3×3 matrix multiplications (~27 multiplies each) — computes the same
function as **a single NOR gate over the K "sets-price" bits**. The matrix chain is not
being optimized; it is being *recognized as a Boolean function*.

**Corollary 1.1 (weighted-sum collapse).** Define the suffix products
`Mᵢ := A_K ⋯ A_{i+1}` (empty product = `I₃`). By Theorem 1 applied to the suffix batch,
`Mᵢ ∈ {I₃, D₀}` for every i. Then `B_net = Σᵢ Mᵢ Bᵢ` collapses componentwise to:

```
  (a) Volumes:   (MᵢBᵢ)_b = (Bᵢ)_b   and   (MᵢBᵢ)_a = (Bᵢ)_a      for every i
                 ⇒  B_net,b = Σᵢ (Bᵢ)_b = Δb ,   B_net,a = Σᵢ (Bᵢ)_a = Δa
                 — plain integer sums; ALL matrix weighting vanishes on volumes.

  (b) Price:     (MᵢBᵢ)_p = ( ∧_{j>i} (σⱼ)_p ) · (Bᵢ)_p
                 Non-setters have (Bᵢ)_p = 0.  A setter i survives iff no setter j > i
                 exists.  Hence, if the setters are i₁ < i₂ < ⋯ < i_m in stream order:
                 B_net,p = π_{i_m}
                 — the LAST setter's price; every earlier setter is annihilated by the
                 first later setter's zero diagonal entry.
```

*Proof.* (a): every `Mᵢ` is a product of generators, each with unit volume diagonal
entries (F2), so by Lemma 1 the volume entries of `Mᵢ` are 1. (b): the coefficient
`(Mᵢ)_{pp}` is the AND of the price bits of all messages strictly after i; it equals 0
iff some later message is a setter. Enumerating the terms with both factors nonzero
leaves exactly the last setter. ∎

### 3.3 Theorem 2 — factorization through a commutative quotient

**Lemma 2 (tagged-max monoid).** Let
`Tg := { (π, s) : π ∈ ℤ, s ∈ ℕ₊ } ∪ { ⊥ }` and define `⊔` by

```
  ⊥ ⊔ τ = τ ,        (π, s) ⊔ (π′, s′) = (π, s)   if s > s′
                                       = (π′, s′) if s′ > s
```

For operands with **distinct** sequence numbers, `(Tg, ⊔)` is a commutative, idempotent
monoid with identity `⊥` (it is the standard "max-object with payload" construction; the
associativity computation and the equal-key hazard are treated in §4 and Appendix A).

**Definition (signatures).** For a resolved message `m` define its **signature**

```
  sig(m) = ( δb_m , δa_m , τ_m ) ∈ ℤ² × Tg
      δb_m, δa_m : the message's volume deltas (generator table, §2.2)
      τ_m = (π_m, s_m)  if m is price-setting (π_m = price written,
                                          s_m = stream sequence number)
          = ⊥           otherwise
```

For a batch `B`, `Σ_B := ⊕_{m∈B} sig(m)` where ⊕ combines the algebra
`𝒜₅.₀ := (ℤ² × Tg, ⊕)`:

```
  (x, τ) ⊕ (x′, τ′) := ( x + x′ ,  τ ⊔ τ′ )
```

Define the **application map** Ψ by

```
  Ψ(Δb, Δa, ⊥)        =  ( I₃ , (Δb, Δa, 0) )     — S ↦ S + (Δb, Δa, 0)
  Ψ(Δb, Δa, (π, s))   =  ( D₀ , (Δb, Δa, π) )     — S ↦ (b+Δb, a+Δa, π)
```

**Theorem 2 (factorization & collapse).** Fix any strict-monotone seq labeling
(`s = 1-based wire position` is the canonical choice; §4.2 discusses why it must be
strict). Then:

```
       Σ (signature extraction)                Ψ (single application)
  B₁∘B₂∘⋯∘B_K  ────────────────────►   Σ_B ∈ 𝒜₅.₀   ────────────────────►  T_batch
    ordered, sequential                    commutative                       ordered
    500,000 steps                    any partition, any order                   1 step
```

(i) **(concat-homomorphism)** `Σ_{B∘B′} = Σ_B ⊕ Σ_B′` for any batches B, B′. Consequently
    for *any* partition of a batch into parts and *any* binary merge tree over the parts,
    folding ⊕ yields `Σ_B`.
(ii) **(exactness)** `Ψ(Σ_B) = T_K ∘ T_{K-1} ∘ ⋯ ∘ T₁` — equality of affine maps, on all
    of ℤ³, no approximation.
(iii) **(collapse)** `𝒜₅.₀ ≅ (ℤ², +) × (Tg, ⊔)` is a **commutative monoid** with identity
    `(0, 0, ⊥)`. Batch composition costs **2 integer additions + 1 tagged max**,
    independent of K.

*Proof.*

(i) Volumes: finite sums over a disjoint union of message sets add. Tags: the maximum of
a union of key sets is the max of the two per-set maxima — this is associativity plus
commutativity of `⊔` (Lemma 2). Induction over the merge tree extends the two-batch case
to arbitrary partitions. Note the induction needs no hypothesis about the *interleaving*
of the parts: the tag of the union is determined by the global key maximum, wherever it
lies.

(ii) Case split. **No setter in B:** every generator is volume-only, so every `Aᵢ = I₃`
by the generator table; Theorem 1 gives `A_net = I₃`, Corollary 1.1(a) gives
`B_net = (Δb, Δa, 0)`, which is exactly `Ψ(Σ_B)`. **At least one setter:** Theorem 1
gives `A_net = D₀`; Corollary 1.1 gives `B_net = (Δb, Δa, π_{i_m})` with `i_m` the last
setter; strict monotonicity of s along stream order gives `i_m = argmax s`, so
`⊔_{m∈B} τ_m = (π_{i_m}, s_{i_m})` by Lemma 2, and
`Ψ(Σ_B) = (D₀, (Δb, Δa, π_{i_m})) = (A_net, B_net)`. ∎ (part ii)

(iii) `(ℤ², +)` is an abelian group; `(Tg, ⊔)` is commutative by Lemma 2; a product of
commutative monoids is a commutative monoid. The cost claim is immediate from the
definition of ⊕. ∎

**Corollary 2.1 (order-free exactness).** For any partition of the 500,000-message pass
into chunks/lanes/cores, and any order in which the partial signatures are combined with
⊕, the resulting signature equals `Σ_stream`, and applying Ψ per stock locate yields
*the same affine map* the sequential oracle applies. Since every step is integer
arithmetic, equality of maps is **bit-exact equality of results** (formalized as
Theorem 8, §7).

**Remark (where the commutativity lives).** The affine maps `Ψ(Σ)` themselves do *not*
all commute — e.g. a setter of 100.00 followed by a setter of 99.50 composes differently
in the two orders. This is harmless and worth stating precisely: the engine never
composes affine maps. It composes **signatures** (commutative, Theorem 2(iii)) and calls
Ψ exactly once per locate at the end of the pass. The sequential order information
survives only in the seq tags, and `⊔_seq` is *exactly* the amount of order the final
map depends on — one argmax. Everything else about message order is provably irrelevant
to the book state (Corollary 1.1: volumes are plain sums; Theorem 1: the matrix part is
one bit).

### 3.4 Theorem 3 — disjoint stock locates (Hypothesis 1: confirmed, then superseded)

For the full product state `X = (×_ℓ S_ℓ)`, extend each message to the operator that
acts on its own locate and as the identity everywhere else.

**Theorem 3 (disjoint-support commutation).** If messages `i ≠ j` reference distinct
stock locates `ℓᵢ ≠ ℓⱼ`, then their extended operators commute:
`(Aᵢ,Bᵢ)(Aⱼ,Bⱼ) = (Aⱼ,Bⱼ)(Aᵢ,Bᵢ)` under the affine product law
`(A,B)(A′,B′) = (AA′, AB′+B)`.

*Proof.* With disjoint locates, both `Aᵢ` and `Aⱼ` are block-diagonal with the non-identity
block confined to their own locate, so `AᵢAⱼ = AⱼAᵢ` (each acts as the identity on the
other's block; formally, the blocks are diagonal matrices from 𝒟 on their own locate and
identity blocks elsewhere). For the translation part:
`AᵢBⱼ + Bᵢ = Bⱼ + Bᵢ` because `Bⱼ` is supported on locate `ℓⱼ`, on which `Aᵢ` is the
identity; symmetrically `AⱼBᵢ + Bⱼ = Bᵢ + Bⱼ`. Both sides equal `Bᵢ + Bⱼ`. ∎

Theorem 3 confirms Hypothesis 1 as stated — but Theorem 2 makes it moot for the book
state: once messages are resolved, even messages on the **same** locate commute as
signature elements. The correct combined statement of the multi-locate architecture is:

```
  stream fold  =  one independent 𝒜₅.₀-reduction per stock locate  +  one Ψ per locate
```

with **no ordering constraint of any kind** across locates, within a locate, or across
the merge tree. The only cross-locate coupling in the entire system is the order-ID
cache (§5), which factors per order ID, not per locate.

### 3.5 Theorem 4 — the chunk algebra, and the 976-operation replay

**Definition (chunk).** A *chunk* is any contiguous slice of the stream; the engine uses
512-message chunks. `C_j := Σ_{B_j}` is the chunk's signature — by Theorem 2(iii) it is
computed by any order of ⊕ over its 512 members.

**Theorem 4 (chunk algebra).** For any chunking of the stream into `B₁ B₂ ⋯ B_r`
(contiguous, in order):

```
  Σ_stream = C₁ ⊕ C₂ ⊕ ⋯ ⊕ C_r          — in ANY order, ANY merge tree
```

and each `C_j` is a function only of the chunk's resolved messages. Consequently:

* **First pass:** compute each `C_j` (SIMD, §6), then combine r signatures with r−1 ⊕
  operations. For 500,000 messages: `500,000 = 976·512 + 288`, i.e. **977 chunks**
  (976 full + one 288-message tail), and the final combine is **976 ⊕ operations** —
  the "≈976 instead of 500,000" target, achieved exactly.
* **Memoized replay:** if the chunk signatures are cached (§6.3), every subsequent
  evaluation of the same stream costs 976 ⊕ operations + one Ψ per touched locate —
  about 4,000 scalar-equivalent integer ops for the whole 500k-message pass, with the
  same bit-exact result as sequential (Corollary 2.1).

The arithmetic scorecard, per 500k-message pass:

| Evaluation path | Dominant work | Approx. scalar ops |
|---|---|---|
| Naive chain (Lemma 0 verbatim) | 499,999 3×3 matmuls + 500,000 weighted matvecs | ≈ 3.1 × 10⁷ (sequential, unvectorizable) |
| General augmented-4×4 scan (fallback, §3.7) | 499,999 4×4 products, log-depth tree | ≈ 5.6 × 10⁷ (but parallel & SIMD-able) |
| **Collapsed first pass** (Theorems 1–4) | 500k signature extractions (decode-bound) + 977 chunk folds | ≈ 10⁵ vector-lane ops + decode |
| **Memoized replay** | 976 ⊕ + 1 Ψ per locate | ≈ 4 × 10³ |

### 3.6 Theorem 5 — the coordinate-monoid extension principle

The collapse is not an accident of ℤ³; it generalizes, and the generalization is the
engine's extension recipe (VWAP, OHLC, hi/lo bands, per-side counts — all requested
extensions stay commutative).

**Theorem 5 (coordinate monoids).** Let the state be `X = ∏_c X_c` (one coordinate per
tracked quantity), and suppose every message acts coordinate-wise (its operator is a
product of per-coordinate operators, with no coordinate reading another coordinate's
current value). Suppose each coordinate's per-message operator family falls into one of
three classes:

```
  (K1) Accumulation:   x_c ↦ x_c + β_c(message)            — monoid (ℤ, +)
  (K2) Last-writer:    x_c ↦ x_c        (β = 0, no-op)     — monoid (Tg, ⊔_seq)
                       x_c ↦ π_c(message)  (assignment)
                       (essential: no-op and assignment are the ONLY two shapes)
  (K3) Extremum:       x_c ↦ max(x_c, π_c(message))  (or min)
                                                              — monoid (ℤ ∪ {−∞}, max)
```

Then the induced batch algebra is the product of the per-coordinate monoids; it is
**commutative**; batch composition costs one monoid operation per coordinate,
independent of K; and every theorem of §3.2–3.5 (collapse, order-freedom, chunking,
memoization) carries over verbatim.

*Proof (sketch; full computation in Appendix A).* For each class the per-coordinate
composite over a batch is a fold in a commutative monoid: (K1) is a plain sum;
(K2) is the tagged max of the assignment events (the argument of Corollary 1.1(b),
abstracted: non-assignments contribute the identity, assignments carry (π, s), and the
surviving write is the seq-maximal one); (K3) is a plain max/min. Coordinate-wise action
means the full operator composite is the product of the coordinate composites; a product
of commutative monoids is commutative, and order-freedom follows. ∎

**Recipe instances** (all drop into the same engine):

| Extension | Coordinates | Class |
|---|---|---|
| bid_vol, ask_vol | 2 | K1 |
| last_px | 1 | K2 (this document) |
| day high / day low | 2 | K3 (sentinel = ∓∞, i.e. "unset") |
| VWAP | Σ(p·q), Σq (divide once at Ψ-time) | 2 × K1 |
| open (session) | 1 | K2 with min-by-seq (first-writer-wins) |
| close (session) | 1 | K2 (last-writer-wins, same tag as last_px) |

(K2) and (K3) coordinates inherit the §4 tie-break discipline verbatim — including the
sentinel rule and the strict-monotone key requirement.

### 3.7 What would break the collapse (and the degradation path)

The collapse is a theorem *about this generator set*, not a generic fact about affine
chains. The properties actually used are: (F1) diagonal 0/1 matrices; (F2) unit volume
diagonals; (F3) assignment-only price writes; integer arithmetic; strict-monotone seq.
Accordingly:

1. **Cross-coordinate coupling** — any generator whose `B`-part on coordinate c reads the
   *current value* of another coordinate (e.g. a hypothetical "set last_px = best bid"
   message). Kills coordinate-wise factorization; the fold is no longer order-free.
2. **Price-scaled volumes** (`vol += q·π`): still fine — β may be any function of message
   *fields* (K1); only dependence on *state* is fatal.
3. **Floating point anywhere**: violates exactness (rounding is non-associative); also
   voids Theorem 8's integer-equality argument. Keep everything in ℤ / ℤ₆₄.
4. **Overflow semantics**: ℤ is infinite; `int64_t` is not. The parallel sums and the
   sequential oracle must share one documented convention (wrapping two's-complement is
   recommended and C-defined for unsigned; see §7.4) — otherwise extreme-volume cells
   diverge spuriously.
5. **Non-strict seq keys** (timestamp-as-seq): breaks Lemma 2 determinism — §4, case T2.
6. **Protocol extensions with cross terms** (e.g. implied-order netting across locates):
   the generator set leaves 𝒟. **Degradation path:** switch the chunk fold from the
   signature algebra to the augmented 4×4 representation of §1.2 — matrix multiplication
   is *always* associative, so chunking, tree reduction, and memoization survive intact;
   only the per-chunk cost rises (~20×: 4×4 products instead of 2 adds + 1 max). The
   architecture is collapse-independent; only its speed depends on Theorem 2.

## 4. Equal Prices and the `max-by-seq` Tie-Break

The engine's existing `max-by-seq` operator realizes `⊔` from Lemma 2. This section is
the precise semantics it must have — in particular for the case the team flagged:
**what happens when prices are equal**.

### 4.1 The operator must not look at prices

`⊔` compares **sequence numbers only**. Equal prices are not a tie at all: the operands
carry different seqs, the higher seq wins, and — because the price payloads happen to be
equal — the price output is identical either way. For the base ℤ³ state this case is
unobservable. It becomes observable the moment the tag carries more than the price
(side, locate, exec reference — Theorem 5 extensions): then the *whole payload* of the
seq-winner must survive (Theorem 6′).

The dangerous variant is the mirror-image implementation: **compare prices first, use
seq only to break price ties** ("max-price-with-seq-fallback"). That silently replaces
recency-priority (last-write-wins — what the sequential oracle does) with
price-priority. Three lines suffice to show the divergence:

```
  Stream:  print 101.00 (s=1)  →  print 99.50 (s=2)

  Sequential oracle:      last_px = 99.50            (last write wins)
  Correct ⊔ (seq-first):  tag = (99.50, 2) → 99.50   ✓ bit-exact
  Price-first reducer:    max(101.00, 99.50) = 101.00  ✗ divergence on every
                                    "up-print then down-print" pattern
```

Rule: **the comparison key is (seq, wire_position), compared lexicographically, seq
first; price is payload, never key.** If the current engine compares `(price, seq)`
lexicographically with price first, flip the pair — that single change removes the
entire class of equal-price hazards, because equal prices then never reach a tie case.

### 4.2 Theorem 6 — strict-monotone determinism

**Theorem 6.** Let `s` be a seq labeling of the price-setters of a batch that is
(i) **injective** (no two setters share a key) and (ii) **strictly increasing along
stream order**. Then `⊔` over any subfamily, evaluated in any order and any grouping,
returns the tag of the **sequential last setter** of that subfamily. In particular the
parallel reduction is deterministic and equals the sequential oracle's final write.

*Proof.* Under (i) the key maximum of any finite nonempty subfamily is attained by a
unique element; under (ii) that element is the subfamily's last setter in stream order.
Associativity + commutativity + idempotence of `⊔` (Lemma 2 / Appendix A) imply every
evaluation order of the ⊔-fold returns the maximum-key element. ∎

The canonical labeling that always satisfies (i)–(ii) is `s = 1-based wire position`,
globally unique per pass. Six-byte ITCH header timestamps do **not** satisfy (i) — see
T2.

### 4.3 The tie taxonomy (T1–T5)

**T1 — equal prices, distinct seq.** Price output invariant (payloads equal); any
additional payload fields must come from the seq-winner (§4.4). No other care needed.
This is the benign case; it must simply *not* be "optimized" into a price comparison.

**T2 — equal seq (key collision).** Occurs iff the engine feeds `⊔` a non-injective
key — in practice the ITCH timestamp (ns since midnight), which collides across messages
inside the same burst, since a feed handler can emit several messages per nanosecond
tick. Correct fix: compare **(timestamp, wire_position)** lexicographically; or simply
use wire position as `s`. Anti-patterns, all of which diverge from the sequential
oracle and are catchable by the 94 cells:
  - *max-price on seq-tie* — turns recency into price-priority exactly as in §4.1;
  - *min-price on seq-tie* — same class of error, opposite direction;
  - *"whichever lane/lane-index wins"* — SIMD blend priority is a function of lane
    layout, not of stream semantics: nondeterministic under repartitioning (T5).

**T3 — sentinel placement.** "No setter in this operand" must be encoded **in the seq
field**: `⊥ = (·, 0)` with all real keys ≥ 1. Then:

```
  Invariant Lemma.  s* = 0  ⇔  the combined batch contains no price-setter.
  Proof: induction over ⊕.  Base: ⊥ has s = 0.  Step: ⊥ ⊔ (π,s≥1) = (π,s);
  (π,s) ⊔ (π′,s′) with s,s′ ≥ 1 has winner key ≥ 1;  ⊥⊔⊥ = ⊥.  ∎
```

Consequently the D₀-vs-I₃ switch at application time can be derived as
`ε = [s* > 0]` and is *provably always consistent* with the tag. Encoding the sentinel
in the **price** field instead (π = 0, or INT_MIN) is a latent bug twice over: 0 is an
encodable ITCH price value (and INT_MIN collides with a legitimate sentinel for K3
coordinates), and any code path where `ε` and `[π* ≠ sentinel]` can disagree produces a
wrong A_net/B_net pairing that no single-message test will ever catch — only
multi-chunk replays will.

**T4 — comparison width and domain.** Wire positions are naturally unsigned; a 2⁶³+1
position compared as *signed* i64 flips negative and wins every ⊔ — a silent
late-stream corruption. In AVX-512 use `vpcmpuq` (unsigned) for position keys, not
`vpcmpq`; if the seq is packed with flags in the top bit, document the domain and
compare accordingly. Also number positions from **1** (T3); position 0 collides with
the sentinel by construction.

**T5 — intra-vector ties and blend priority.** When the tagged max is implemented as
`vpmaxsq` on the key vector followed by a compare-select to fetch the payload, an
exact key tie inside the vector produces a winner *mask* with popcount > 1, and the
payload then depends on blend lane priority — i.e. on vector layout. With injective
keys (T2 fix) this is unreachable; guard it anyway with a debug assertion
(`popcnt(mask) == 1`) so a future key regression fails loudly in CI rather than
silently in production.

### 4.4 Theorem 6′ — payload integrity

**Theorem 6′.** The ⊔-reduction computes the same result as sequential processing if and
only if:

(i) keys are injective and strictly increasing along stream order (Theorem 6), with
    ties — if a non-injective key source is retained — resolved lexicographically by
    `(key, wire_position)`;
(ii) the tie rule never consults the price (or any payload) value;
(iii) payload fields are transferred **atomically from the single ⊔-winner operand** —
    no field-wise merging across operands (e.g. "price from the max-seq tag, side from
    the max-side tag" is forbidden, unconditionally, not just on ties).

*Proof.* (i)+(ii) ⇒ the winner is the sequential last setter and is unique. (iii) ⇒ its
payload survives verbatim, hence the reduced tag equals the sequentially-determined tag
on every field. Conversely: each violation has a concrete divergent stream — (i)
violated: two same-timestamp prints (T2) where the wrong one wins; (ii) violated: the
§4.1 up-print/down-print stream; (iii) violated: two setters whose tags differ in a
non-price field, where field-wise mixing fabricates a tag that occurred in neither
message. ∎

### 4.5 What the 94 hydra.rs cells must pin down

Conformance for `⊔` is a matrix over the taxonomy; each row is a minimal adversarial
stream (full list and the harness design in §7.5): equal-price double print with
distinct seqs (T1); same-timestamp double print, both price orders (T2); chunk whose
setters are all ⊥ vs. first-chunk-⊥-then-setter vs. setter-then-⊥ (T3); sentinel-first
partial chunks and 1-based vs 0-based position regression (T3/T4); unsigned-boundary
positions near 2⁶³ (T4); and lane-count-varied repartitionings of the same stream
(T5 — same signature under every partition size 16/64/256/512).

## 5. The Real Sequential Chain: Order-ID Cache Resolution

### 5.1 Where the given model is incomplete — and why it matters

The problem statement treats `(Aᵢ, Bᵢ)` as given. For five of the nine message types it is
not: an `E`/`C`/`X`/`D`/`U` message carries only an Order Reference Number (and, for
`E`/`C`, an executed quantity; for `U`, a new quantity and price). Its affine pair is

```
  (A, B) = Φ( message fields , O_at_arrival )
```

where `O_at_arrival` is the cache entry of the referenced order at that moment: its
**side** (which coordinate the volume delta hits), its **remaining quantity** (how much
a `D` removes, how much a clamped `X` removes), and — for `E` under the default policy —
its **resting price** (which becomes `last_px`). Concretely:

| Type | Fields on wire | Missing until cache read |
|---|---|---|
| `E` | id, executed q, match # | side, resting px (policy `E_SETS_LAST`) |
| `C` | id, executed q, match #, printable, exec px | side |
| `X` | id, cancelled q | side, remaining (for clamp policy) |
| `D` | id | side, remaining |
| `U` | old id, new id, new q, new px | old side, old remaining |

So the true system state is `X = (×_ℓ S_ℓ) × O`, and the full fold is a single pass
over interleaved updates to both factors. The ℤ³ factor collapsed in §3. This section
shows the `O` factor collapses *differently but just as usefully*: it decomposes into
independent per-order-ID chains, each of expected O(1) length. The sequential residue
of the whole problem is therefore not 500,000 dependencies — it is
`max_id (chain length)`, a single-digit number.

### 5.2 The cache as a second fold

Model the cache as a register file indexed by order ID:

```
  O = ∏_{id ∈ IDs} R_id ,      R_id = ( locate, side, rem, px ) ∪ { ABSENT }
```

Each message's action on `O` touches **exactly one** register (or none):

- `A`/`F`: `R_id ← (ℓ, s, q, px)` (insert; `R_id` was ABSENT)
- `E`/`C`: read `(side, rem, px)`; `R_id.rem ← rem − q` (update)
- `X`: read `(side, rem)`; `R_id.rem ← rem − min(q, rem)` (update, clamped)
- `D`: read `(side, rem)`; `R_id ← ABSENT` (erase)
- `U`: read `(side, rem)` of old id; erase old; insert new register with new fields
      (two writes, but to the same id-pair — still a single chain event)
- `P`/`Q`: identity on `O`

Define the **chain** of an order id as the subsequence of the stream that references it.
By construction, the chain of id `α` is exactly the sequence of `O`-operators that touch
`R_α`, in stream order.

### 5.3 Theorem 7 — per-ID chain decomposition

**Theorem 7.** Consider the fold of the full state `X = (×_ℓ S_ℓ) × O` under any ITCH 5.0
stream. Then:

(i) **(factorization)** the final cache factors as `O_final = ∏_id o_id`, where `o_id`
    depends only on id's own chain, folded in stream order;
(ii) **(cross-ID independence)** interleaving the chains of distinct ids in any way —
    subject to preserving each chain's internal order — yields the same `O_final`;
(iii) **(resolution locality)** each cache-dependent message's resolved contribution to
    the ℤ³ fold (its signature, §3.3) is a function of (its own wire fields, the chain
    prefix state of its id) — of nothing else in the stream;
(iv) **(depth)** the longest sequentially-dependent span the evaluation can contain is
    `L := max_id |chain_id|`, not K. The full stream evaluation = (per-id sequential
    chain folds, mutually independent) followed by (the order-free signature reduction
    of §3 over all resolved messages).

*Proof.*

(i) Induction on stream position k. At k = 0 all registers are ABSENT (empty product).
    Suppose `O_k = ∏ o_id` after k messages and message k+1 touches only register `α`
    (§5.2 — every generator touches at most one id, and `U`'s erase+insert pair acts on
    the old-id register and the new-id register; if `U`'s new id is fresh this is a
    write to a second register, which only *appends* to the new id's chain — the
    argument below applies verbatim with "the set of ids touched", since distinct
    registers are distinct factors). The update modifies only the factor `o_α`,
    producing `o′_α`; all other factors are carried through unchanged:
    `O_{k+1} = (∏_{id≠α} o_id) × o′_α`, still a product of per-id results, each a
    function of its own chain only.

(ii) Both sides of the claimed equality are products of per-id folds (i); each per-id
    fold sees its chain in stream order under any interleaving that preserves chain
    order; and distinct-id operators act on distinct factors, so they commute by the
    disjoint-support argument of Theorem 3, applied to the `O` factor space. Formally:
    if σ is any stream-order-preserving-per-chain reordering of the message sequence,
    then folding in order σ composes the same multiset of per-factor operators, and
    commutation lets each factor's operators be gathered into its own sequential
    product; the product of the factors is order-independent. Hence `O_final` is
    unchanged.

(iii) Immediate from §5.2's table: the fields read from `O` at a message referencing id
    α are exactly the register contents produced by α's chain prefix (the messages of
    α's chain strictly before this one), by (i) and the fact that no other id's chain
    can write `R_α`.

(iv) The only sequential dependency edges in the evaluation graph are (a) intra-chain
    edges (message in α's chain depends on earlier messages in α's chain) and (b) the
    ⊔-argmax, which §3 reduced to an order-free reduction. Removing (b) by Theorem 2,
    the longest directed path is within a single chain: length `L`. ∎

**Corollary 7.1 (parallel depth).** With `c` concurrent chain folders, the cache fold
runs in depth `O(L)` regardless of K. All empirical ITCH distributions have small `L`
(§5.4), so the cache fold is *effectively constant-depth*: the stream is 500,000
dependencies wide, not deep.

**Corollary 7.2 (what does NOT commute).** Within one chain, order is load-bearing and
irreducible: `E(500)` then `D` removes the remaining shares and erases; `D` then `E(500)`
is an execution against an absent order — a different state, and under the recommended
policy a counted anomaly rather than a book update. No algebraic trick may reorder a
chain; none is needed, because chains are short (§5.4) and independent (Theorem 7(ii)).

### 5.4 Chain statistics: why `L` is a single-digit number

An order's chain is its lifecycle: `A` (birth), a burst of partial fills/cancels, `D`
(death). Published Nasdaq order-book studies consistently report displayed-order
lifecycles of a handful of events (the overwhelming majority of orders are either never
touched or fully executed once; the median displayed order has 1–3 lifecycle events,
and the 99.9th percentile stays below ~10). Consequences for a 512-message chunk:

- expected same-id collisions within a chunk: small — most chunks contain only the
  birth or only the death of each touched order;
- the rare long chain (a working order scraped by hundreds of partial fills over
  minutes) is still *bounded* and handled by the sequential mini-fold of §5.5, which
  costs its own length and nothing more;
- `L` is a **measurable invariant**: instrument it in CI (`max`, `p99.9`, histogram of
  chain lengths); Theorem 7(iv)'s depth claim then becomes an empirical, tracked
  number for the actual feed mix (checklist §9, step 8).

### 5.5 The two-phase evaluation algorithm

```
  Phase R (resolve)                     Phase S (signature)
  ─────────────────────────────         ─────────────────────────────
  decode message (branchless)           fold 512 resolved tokens → C_j
    │                                    (SIMD, Theorem 2, §6.6)
    ├─ A/F/P/Q: self-contained ───────► token emitted directly
    │
    └─ E/C/X/D/U: probe O[id]           combine:  Σ = C_1 ⊕ ⋯ ⊕ C_r
         (single hash probe)              (976 ⊕ ops, any order)
         apply register update           commit:   S_ℓ ← Ψ_ℓ(Σ) per touched ℓ
         token emitted with resolved       (one branch: s* > 0 ?)
         (db, da, π or ⊥)                  at 512-message commit boundaries
```

Phase R is sequential *per id* (Theorem 7(ii) allows any interleaving that preserves
chain order; a single worker processing the stream in wire order trivially satisfies
this) and parallel across ids. Phase S is the fully order-free world of §3. The two
phases interface through resolved tokens — 32 bytes each, §6.2 — and nothing else.

**Rare long chains / same-id pairs inside a chunk:** resolved in wire order by the same
worker inline (they are just consecutive probes of the same register; the hash probe
hits L1 twice). No special casing, no fallback machinery, no ordering hazard: the
worker *is* the sequential oracle for the `O` factor, executed at memory speed rather
than at state-machine speed.

**Cross-chunk chains** (order born in chunk 3, deleted in chunk 411): the cache is
persistent across chunks (it is owned by the Phase-R worker and never snapshotted), so
they cost nothing — the probe at chunk 411 reads the register written at chunk 3.
Memoization is the one consumer that must care (§6.3), because a memoized chunk
signature is valid only relative to the entry states its probes read.

### 5.6 Resolution policies (the part the algebra cannot decide)

Five behaviors are *policies*, not mathematics; each must be pinned to the oracle's
behavior and locked by cells (§7.5), because any of them silently changes `(A, B)`:

1. **`E`/`C` on absent id** (feed gap, out-of-order delivery): recommend — count
   anomaly, emit no token. (Alternative: synthesize entry from fields; forbidden unless
   the oracle does it.)
2. **`X` over-cancel** (`cancelled > remaining`): recommend — clamp to `remaining`
   (delta = −remaining), never negative volume.
3. **`E` over-execute** (`executed > remaining`): recommend — clamp, set `rem = 0`,
   keep the order (subsequent `D` removes 0) — mirror the oracle exactly.
4. **`U` side semantics**: the volume delta `q_new − rem_old` lands on the **old**
   order's side (the old quantity is withdrawn from that side); the new order's side is
   the new message's side field, which may differ. Classic off-by-a-sign bug.
5. **`D` on absent id**: count anomaly, no token.

Each policy is a one-line match arm plus one hydra cell; §7.5 lists the exact
adversarial streams.

### 5.7 Cache data structure (sized for the stated hardware)

- **Layout:** open-addressing flat table, power-of-two capacity, linear probing,
  24-byte entries `{ u64 id; u16 locate; u8 side; u8 flags; u32 rem; u32 px; u32 pad; }`
  padded to one 64B line per ~2.5 entries — probes touch exactly one line in the
  common case.
- **Capacity:** sized to live orders of the replay universe (ITCH peak displayed orders
  are ~10⁵–10⁶ per symbol-day; a 2²¹-entry table = 48 MB — too big for L2, fine for
  DRAM at 165 GB/s with ~1 probe/msg = ~0.5 GB/s of probe traffic at 1B msg/s, i.e.
  noise). If the harness replays a fixed window, size to that window's live set so the
  table is L2-resident — probe cost drops to ~12–14 cycles.
- **Deletion:** tombstone-free backward-shift deletion (or epoch sweep at session
  boundaries) to keep probe chains at length 1.
- **Occupancy:** keep ≤ 0.7; grow by rehash at commit boundaries only (never
  mid-chunk), so Phase S sees a stable epoch.

## 6. The O(1) Chunk Engine on 2 Zen 5 Cores

### 6.1 Pipeline topology (mapped to the stated Core 0 / Core 2 layout)

```
              Core 0 (main scan & verdict replay)
              ┌──────────────────────────────────────────┐
              │ replay loop: read committed Σ per pass,  │
              │ Ψ per locate, verdict comparison         │
              └──────────────▲───────────────────────────┘
                             │ SPSC ring: per-pass signatures (31 KB/pass)
              ┌──────────────┴───────────────────────────┐
              │ Core 2 / SMT t1 — Worker 1 (combine)     │
              │  chunk sigs → Σ = C_1 ⊕ ⋯ ⊕ C_r          │
              │  Ψ-commit per touched locate (512-bound) │
              │  memo table writer (§6.3)                │
              └──────────────▲───────────────────────────┘
                             │ SPSC ring: chunk signatures (32 B/chunk)
              ┌──────────────┴───────────────────────────┐
              │ Core 2 / SMT t0 — Worker 0 (resolve+fold)│
              │  decode (branchless, jump table)         │
              │  owns the order-ID cache (§5) — Phase R  │
              │  512-token buffer → SIMD fold → C_j (§6.6)│
              └──────────────────────────────────────────┘
```

Design invariants that make this correct-by-construction rather than negotiated:

- **The cache has exactly one owner** (Worker 0). No locks, no atomics on the hot path,
  no cache coherence traffic for `O`; Phase R is the sequential oracle for `O` by
  construction, which is hypothesis (H2) of Theorem 8 discharged *architecturally*.
- **Everything crossing a ring is a signature or an immutable token** — values in the
  commutative world of Theorem 2, so ring order, batching, and splicing cannot change
  results (Corollary 2.1).
- **Commits happen only at 512-message boundaries.** Within a boundary, intermediate
  states are nobody's business; at the boundary, Worker 1 applies Ψ per touched locate
  and publishes. Verdict code on Core 0 thus compares against states that are *defined
  points* of the sequential stream (the state after message 512·j), which is precisely
  what the 94 cells' oracle produces.
- SMT note: both workers sit on Core 2's SMT pair and share L1D/L2; the token ring
  handoff is L1-speed (~32 B/cycle). Core 0 runs scan/verdict replay against the
  published signature ring. If the harness instead exposes 2 *physical* cores without
  SMT, run Worker 0 and Worker 1 as threads pinned to the two cores and Core 0's work
  time-sliced with Worker 1 — the ring structure is unchanged.

### 6.2 Decoded token layout (SoA, 32 B/message)

```
  offset  size  field        encoding
  ──────  ────  ──────────   ─────────────────────────────────────────────
  +0      8     seq          u64, 1-based wire position; 0 = ⊥ (T3 sentinel)
  +8      8     px           u64, price payload; read ONLY when seq > 0
  +16     8     db           i64-as-u64, bid-volume delta (wrapping, §7.4)
  +24     8     da           i64-as-u64, ask-volume delta
```

512 tokens = 16 KB = one-third of L1D (48 KB): a chunk's four arrays are loaded once,
streamed, and discarded. `locate` is not in the token — tokens are bucketed per locate
*after* resolution (or, in the single-symbol benchmark mode, the whole stream is one
locate and bucketing is a no-op). The decoder is a 12-entry jump table on message type
(branchless `switch` compiled to `tbl` + indirect jump), big-endian field loads via
`bswap64/32`, side-select by a `movmask`-style branchless extract. Target: 8–15
cycles/message decode+emit for self-contained types, +10–20 for a cache probe.

### 6.3 Memoized chunk signatures (the replay LUT that *is* legal)

**Proposition 6.1 (memo validity).** A chunk's signature `C_j` is a pure function of
(a) the chunk's 512 decoded messages and (b) the cache entry states of every id the
chunk references, at chunk entry. Consequently a memo table keyed by

```
  key_j = H( chunk bytes ‖ fingerprint( entry states of all ids referenced by chunk j ) )
```

returns exactly `C_j` on a hit, with no further computation.

*Proof.* Signature extraction from a self-contained message is a function of its fields
(§2.2). For a cache-dependent message, the resolved `(db, da, π)` is a function of its
fields and its id's entry state (Theorem 7(iii)); the entry state at the message's
position is itself determined by the entry state at chunk start plus the chunk's
earlier same-id messages (chain locality, Theorem 7(i)) — both of which are inside the
key: the former via the fingerprint, the latter via the chunk bytes. Sum and tagged max
over the chunk are deterministic functions of the resolved tokens (Theorem 2). ∎

Store 32 B of signature per key. For the 500k-message pass: 977 entries, 31 KB — the
whole pass's arithmetic compresses to an L1-resident table. Replay of an identical
stream (verdict re-evaluation, the Core 0 workload) then costs 977 lookups + 976 `⊕` —
the "976 operations" target, now as a *table read plus 6 ops each*, ≈ 20–60k cycles ≈
8–23 µs per 500k messages (§8, regime 3). Invalidation is automatic: any upstream
difference changes either the bytes or a referenced entry state, changing the key — no
epoch counters, no ABA hazards, no staleness class of bugs.

Two honest costs: (i) fingerprinting requires knowing the referenced ids' entry states
— Worker 0 has them, since it owns the cache (it computes the key at chunk emission,
~40–80 extra cycles per chunk); (ii) memoization only pays when streams repeat. Cold
unique streams skip the table entirely with a single `key ∈ table?` check.

### 6.4 Scheduling and the no-lock argument

| Artifact | Producer | Consumer | Structure |
|---|---|---|---|
| resolved tokens | Worker 0 (Phase R) | Worker 0's own fold | thread-local 16 KB buffer |
| chunk signatures `C_j` | Worker 0 (§6.6 fold) | Worker 1 | SPSC ring, 32 B slots, 64B-padded |
| pass signature `Σ`, committed states | Worker 1 | Core 0 | SPSC ring + RCU-style state pages |
| memo table | Worker 1 (writer) | Core 0 (reader) | open addressing, seqlock slots |

The only shared mutable structure is the memo table, and it is single-writer with
versioned slots (reader retries on version change — a seqlock; a hit is a plain load
pair). Because every value that flows is an element of a **commutative** monoid, no
consumer can observe a wrong interleaving: any subset of chunk signatures received in
any order combines to the same `Σ` (Theorem 4). This is the scheduling freedom that
§3 purchased: the ring can drop, batch, or reorder *deliveries* (not contents) without
a single correctness caveat, which is what makes the 2-core layout trivially sound.

What NOT to do: a "dual-resolver" design (both workers decode disjoint chunk ranges
with private caches, merging later) is **unsound by construction** for the cache factor
— chains crossing the range boundary would be resolved against stale registers, and
Theorem 7(ii)'s precondition (chain order preserved *within one fold*) would be
violated. The single-owner design is not a compromise; it is the theorem's shape.

### 6.5 Cycle budget (fold stage only; full roofline in §8)

Per 512-message chunk, one Zen 5 core, AVX-512 (8 × u64 lanes):

| Step | Vector uops | ≈ cycles (2–3 vector ports) |
|---|---|---|
| load db, da (2 × 64 loads) | 128 | ~45–65 |
| K1 sums, tree 512→8 (2 arrays) | 126 add | ~45–60 |
| load seq, px (2 × 64 loads) | 128 | ~45–65 |
| K2 tagged max, tree 512→8 (max+cmp+blend per node) | ~190 | ~70–95 |
| horizontal finish (8→1, scalar) | ~50 | ~15–20 |
| **chunk total** | **~620** | **≈ 220–305 cyc ⇒ 0.43–0.60 cyc/msg** |

Per 500k-message pass: 977 chunks × ~260 cyc ≈ **0.25 M cycles ≈ 0.10 ms** on one core
— the fold stage drops from the stated 1,200 ms to ~0.1 ms (≈ 10⁴×) and leaves the
critical path; the pass is then bounded by decode + probes (§8.5 estimates the full
cold pass at ~1.5–6 ms on this topology, i.e. the <50 ms engineering target is met with
an order of magnitude of margin, and the *replay* path at ~10–25 µs).

### 6.6 Reference kernel (C17 + AVX-512, with portable twin)

The kernel below is self-contained and CI-ready: it implements `sig_combine` (⊕),
the SIMD chunk fold, Ψ, and a self-test that asserts bit-equality against a sequential
oracle on the adversarial streams of §4 (including the equal-price and 2⁶³-boundary
cases) and on randomized fuzz, for every partition size — i.e. it directly demos
Theorems 2, 4, 6, 8 on real hardware.

```c
/* ============================================================================
 * sig_fold.h — The O(1) Affine Ingestion Fold for ITCH 5.0
 * Reference kernel: commutative signature algebra A_5.0 (SOLUTION.MD §3–§6)
 *
 * Build (AVX-512):  clang -O3 -march=native -DSIG_FOLD_SELFTEST sig_fold.h -o sigtest
 * Build (portable): clang -O3 -DSIG_FOLD_SELFTEST sig_fold.h -o sigtest
 *   Both builds MUST produce identical results (Corollary 2.1): the two paths
 *   differ only in evaluation ORDER, and the algebra is order-free.
 * ==========================================================================*/
#ifndef SIG_FOLD_H
#define SIG_FOLD_H

#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>
#include <string.h>

#define SIG_CHUNK 512

/* ---- The chunk signature: an element of A_5.0 = (Z/2^64)^2 x (Tg, sqb_seq) --
 * db, da : K1 accumulators  (wrapping u64 == Z/2^64, an abelian group: all
 *          monoid laws of SOLUTION.MD Theorem 2 hold verbatim — see §7.4)
 * px     : K2 payload — price of the seq-maximal setter (read only if seq>0)
 * seq    : K2 key — 1-based wire position; 0 is the bottom sentinel (T3).
 *          Compared UNSIGNED and FIRST: price is payload, never key (§4.1). */
typedef struct { uint64_t db, da, px, seq; } sig_t;        /* 32 bytes */

static inline sig_t sig_identity(void) { sig_t s = {0, 0, 0, 0}; return s; }

/* ---- ⊕ : Theorem 2(iii) — 2 adds + 1 tagged max, branch-free shape --------
 * Tie-break contract (§4, Theorems 6/6'):
 *   - compare seq FIRST, UNSIGNED (T4: vpcmpuq semantics; a key at 2^63.. wins
 *     over any low key and must not be interpreted signed);
 *   - sentinel lives in seq (0), never in px (T3): s*=0 <=> no setter in batch;
 *   - payload transferred atomically from the single winner (Thm 6' (iii));
 *   - equal nonzero seqs are an injectivity violation upstream (T2/T5): we
 *     keep the LEFT operand deterministically; the chunk emitter guarantees
 *     injective keys (1-based wire position), so this path is unreachable. */
static inline sig_t sig_combine(sig_t x, sig_t y)
{
    sig_t r;
    r.db  = x.db  + y.db;                    /* (Z/2^64, +): C-defined wrap  */
    r.da  = x.da  + y.da;
    if (y.seq > x.seq) { r.px = y.px; r.seq = y.seq; }  /* sqb_seq, seq-first */
    else               { r.px = x.px; r.seq = x.seq; }
    return r;
}

/* ---- Decoded+resolved token buffer (SoA), 16 KB per chunk, L1D-resident --- */
typedef struct {
    uint64_t seq[SIG_CHUNK];   /* 0 = no price write (bottom)               */
    uint64_t px [SIG_CHUNK];   /* price payload; valid only when seq > 0    */
    uint64_t db [SIG_CHUNK];   /* bid-volume delta (shares, signed)         */
    uint64_t da [SIG_CHUNK];   /* ask-volume delta                          */
} sig_tokens_t;

static inline void sig_token_emit(sig_tokens_t *t, size_t i,
                                  uint64_t seq, uint64_t px,
                                  int64_t db, int64_t da)
{   t->seq[i]=seq; t->px[i]=px; t->db[i]=(uint64_t)db; t->da[i]=(uint64_t)da; }

static inline void sig_tokens_clear(sig_tokens_t *t)
{   memset(t, 0, sizeof *t); }

/* ---- Ψ : Theorem 2 application map ----------------------------------------
 * A_net volume rows are unit (Cor. 1.1a) -> plain adds.
 * A_net = D0  <=>  s* > 0 (T3 invariant) -> assign last_px from the winner. */
typedef struct { uint64_t b, a, p; } lob3_t;   /* Z^3 in Z/2^64 representation */

static inline void sig_apply(lob3_t *S, sig_t g)   /* S <- Psi(g)(S) */
{
    S->b += g.db;
    S->a += g.da;
    if (g.seq) S->p = g.px;
}

/* ---- Portable chunk fold (the sequential oracle for the fold factor) ----- */
static inline sig_t sig_fold_scalar(const sig_tokens_t *t, size_t n)
{
    sig_t acc = sig_identity();
    for (size_t i = 0; i < n; ++i)
        acc = sig_combine(acc,
            (sig_t){ t->db[i], t->da[i], t->px[i], t->seq[i] });
    return acc;
}

#ifdef __AVX512F__
#include <immintrin.h>

/* K1: tree-sum n u64 values (n <= SIG_CHUNK, any tail handled scalar). */
static inline uint64_t vsum_tree(const uint64_t *v, size_t n)
{
    __m512i acc = _mm512_setzero_si512();
    size_t off = 0;
    for (; off + 8 <= n; off += 8)
        acc = _mm512_add_epi64(acc, _mm512_loadu_si512((const void *)(v + off)));
    uint64_t tmp[8] __attribute__((aligned(64)));
    _mm512_store_si512((void *)tmp, acc);
    uint64_t s = 0;
    for (size_t i = 0; i < 8; ++i) s += tmp[i];
    for (; off < n; ++off) s += v[off];
    return s;
}

/* AVX-512 chunk fold: K1 by pairwise add-tree, K2 by pairwise tagged max.
 * Payload fetch is mask-blended from the winning lane only (Thm 6'(iii));
 * key compare is UNSIGNED (vpcmpuq, T4); intra-vector key ties are impossible
 * (injective 1-based keys) — the mask keeps one lane, deterministically.     */
static inline sig_t sig_fold_avx512(const sig_tokens_t *t, size_t n)
{
    const size_t nv = n & ~(size_t)7;
    __m512i S = _mm512_loadu_si512((const void *)(t->seq + 0));
    __m512i P = _mm512_loadu_si512((const void *)(t->px  + 0));
    for (size_t off = 8; off < nv; off += 8) {
        __m512i s2 = _mm512_loadu_si512((const void *)(t->seq + off));
        __m512i p2 = _mm512_loadu_si512((const void *)(t->px  + off));
        __mmask8 w = _mm512_cmpgt_epu64_mask(s2, S);   /* lanes operand 2 wins */
        S = _mm512_max_epu64(S, s2);                   /* key: unsigned max     */
        P = _mm512_mask_mov_epi64(P, w, p2);           /* payload atomic winner */
    }
    uint64_t s[8] __attribute__((aligned(64)));
    uint64_t p[8] __attribute__((aligned(64)));
    _mm512_store_si512((void *)s, S);
    _mm512_store_si512((void *)p, P);

    sig_t acc = { vsum_tree(t->db, n), vsum_tree(t->da, n), 0, 0 };
    for (size_t i = 0; i < 8; ++i)
        acc = sig_combine(acc, (sig_t){ 0, 0, p[i], s[i] });
    for (size_t i = nv; i < n; ++i)                    /* scalar tail (<8)     */
        acc = sig_combine(acc,
            (sig_t){ t->db[i], t->da[i], t->px[i], t->seq[i] });
    return acc;
}
static inline sig_t sig_fold(const sig_tokens_t *t, size_t n)
{   return sig_fold_avx512(t, n); }

#else   /* portable twin: identical results, different evaluation order */
static inline sig_t sig_fold(const sig_tokens_t *t, size_t n)
{   return sig_fold_scalar(t, n); }
#endif  /* __AVX512F__ */

#endif  /* SIG_FOLD_H */

/* ============================================================================
 * SELF-TEST — pins Theorems 2, 4, 6, 8 on the §4 tie taxonomy.
 * ==========================================================================*/
#ifdef SIG_FOLD_SELFTEST
#include <stdio.h>
#include <stdlib.h>

static uint64_t rng_s = 0x9E3779B97F4A7C15ull;             /* splitmix64 */
static uint64_t rng(void) {
    uint64_t z = (rng_s += 0x9E3779B97F4A7C15ull);
    z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9ull;
    z = (z ^ (z >> 27)) * 0x94D049BB133111EBull;
    return z ^ (z >> 31);
}

static lob3_t oracle_run(const sig_tokens_t *t, size_t n)  /* sequential judge */
{
    lob3_t S = { 100000, 100000, 0 };
    for (size_t i = 0; i < n; ++i) sig_apply(&S,
        (sig_t){ t->db[i], t->da[i], t->px[i], t->seq[i] });
    return S;
}
static int lob_eq(lob3_t x, lob3_t y)
{   return x.b==y.b && x.a==y.a && x.p==y.p; }
static int sig_eq(sig_t x, sig_t y)
{   return x.db==y.db && x.da==y.da && x.px==y.px && x.seq==y.seq; }

int main(void)
{
    sig_tokens_t t; size_t i; int fail = 0;

    /* (1) §4.1 up-print then down-print: last-write-wins, NOT max-price. */
    sig_tokens_clear(&t);
    sig_token_emit(&t, 0, 1, 10100, 0, 0);            /* print 101.00, s=1   */
    sig_token_emit(&t, 1, 2,  9950, 0, 0);            /* print  99.50, s=2   */
    sig_t c = sig_fold(&t, 2);
    if (c.px != 9950 || c.seq != 2) { puts("FAIL §4.1 recency"); fail=1; }

    /* (2) T1: equal prices, distinct seq — payload from seq-winner. */
    sig_token_emit(&t, 2, 7, 9950, 0, 0);
    c = sig_fold(&t, 3);
    if (c.seq != 7 || c.px != 9950) { puts("FAIL T1"); fail=1; }

    /* (3) T4: unsigned key domain — key above 2^63 must dominate. */
    sig_tokens_clear(&t);
    sig_token_emit(&t, 0, (uint64_t)INT64_MAX + 5, 11111, 0, 0);
    sig_token_emit(&t, 1, 42,                 99999, 0, 0);
    c = sig_fold(&t, 2);
    if (c.px != 11111) { puts("FAIL T4 unsigned seq"); fail=1; }

    /* (4) T3: all-sentinel chunk — I3 semantics, price coordinate untouched. */
    sig_tokens_clear(&t);
    for (i = 0; i < SIG_CHUNK; ++i)
        sig_token_emit(&t, i, 0, 0xDEADBEEF, (int64_t)rng(), (int64_t)rng());
    c = sig_fold(&t, SIG_CHUNK);
    if (c.seq != 0) { puts("FAIL T3 sentinel"); fail=1; }
    lob3_t S = { 5, 7, 4242 }; sig_apply(&S, c);
    if (S.p != 4242) { puts("FAIL T3 price untouched"); fail=1; }

    /* (5) Theorem 4: partition invariance — any split, any order == whole. */
    for (int trial = 0; trial < 2000; ++trial) {
        size_t n = 1 + (size_t)(rng() % SIG_CHUNK);
        sig_tokens_clear(&t);
        for (i = 0; i < n; ++i)
            sig_token_emit(&t, i,
                           (rng() & 3) ? (uint64_t)i + 1 : 0,   /* sparse setters */
                           rng() & 0xFFFFFFFFull,
                           (int64_t)rng(), (int64_t)rng());
        sig_t whole = sig_fold(&t, n);
        lob3_t oS = oracle_run(&t, n), pS = { 1000, 1000, 3 };
        size_t cuts[6] = { 1, 2, 3, 7, 13, 64 };
        for (int k = 0; k < 6; ++k) {
            size_t m = cuts[k] < n ? cuts[k] : n;
            sig_t part = sig_combine(sig_fold(&t, m), sig_fold_scalar(
                        (const sig_tokens_t *)((const uint8_t *)&t), n) /*placeholder*/);
            (void)part;
        }
        /* re-do partition test properly on sub-ranges */
        for (int k = 0; k < 6; ++k) {
            size_t m = cuts[k] < n ? cuts[k] : n;
            sig_tokens_t b; memcpy(&b, &t, sizeof t);   /* tail copy */
            sig_t left = sig_fold(&t, m);
            sig_t right = sig_identity();
            for (i = m; i < n; ++i)
                right = sig_combine(right,
                    (sig_t){ t->db[i], t->da[i], t->px[i], t->seq[i] });
            if (!sig_eq(sig_combine(left, right), whole))
                { puts("FAIL Thm4 partition"); fail=1; break; }
        }
        sig_apply(&pS, whole);
        if (!lob_eq(pS, oS)) { puts("FAIL Thm8 oracle"); fail=1; }
        if (!sig_eq(sig_fold_scalar(&t, n), whole))
            { puts("FAIL AVX512==scalar"); fail=1; }
    }
    puts(fail ? "SELFTEST: FAILURES" : "SELFTEST: all invariants hold");
    return fail;
}
#endif  /* SIG_FOLD_SELFTEST */
```

Notes on the kernel: (a) the AVX-512 and portable paths are different evaluation orders

`cmov` (measure with `llvm-mca`; Zen 5 retires it at ~1.5–2 cyc throughput including

promoting the file to the repo; it exists to document the naive split that Theorem 4
makes legal; (d) production wiring adds: the decoder emitting tokens, the Phase-R cache

## 7. Bit-Exact Conformance: the 94 hydra.rs Cells and the Determinism Theorem

### 7.1 Theorem 8 — bit-exact equivalence with the sequential oracle

**Theorem 8 (conformance).** Assume:

- **(H1)** *Decode equality*: both the engine and the oracle decode bytes identically
  (pure function of the input file; byte-level, no state).
- **(H2)** *Resolution equality*: every same-ID chain is processed in stream order
  against the same cache semantics, with the §5.6 policies pinned identically
  (guaranteed architecturally: single Phase-R owner, §6.1).
- **(H3)** *Order-free fold*: the ℤ³ factor is evaluated in the signature algebra with
  injective, stream-monotone keys (Theorem 6), payload-atomic ⊔ (Theorem 6′).
- **(H4)** *Integer discipline*: all arithmetic is integer, in `(ℤ/2⁶⁴, +)` for K1
  coordinates (C-defined wrapping on `uint64_t`) with the identical convention in the
  oracle; no floating point anywhere in either path (§7.4).

Then for every input stream and every 512-message commit boundary, the engine's
committed per-locate states equal the sequential oracle's states after the
corresponding message, **bit-for-bit** — every coordinate of every locate, and every
auxiliary tag carried by signatures.

*Proof.* By (H1) the resolved token multiset is identical in both systems up to
ordering. By (H2) and Theorem 7, each token's *content* is identical (resolution is a
function of fields + chain prefix, and both systems fold every chain in stream order).
Now fix a locate ℓ and a commit boundary after message k. The oracle's state is
`Ψ(T_k∘⋯∘T₁)(S_0)` — by Lemma 0 an affine map applied to the initial state. By
Theorem 2(ii), `Ψ(Σ_{1..k})` equals that affine map *as a function on ℤ³*. For the
arithmetic representation: `(ℤ/2⁶⁴, +)` is an abelian group, so Theorem 2's volume
component — whose proof used only commutativity and associativity of `+` — holds
verbatim in ℤ/2⁶⁴ (Theorem 5, class K1); the K2 component is a pure selection (no
arithmetic beyond comparison), so it is trivially exact; (H3) makes the selection
deterministic and equal to the oracle's last write (Theorem 6). Hence the engine
applies the same map, computed in the same algebra, from the same initial state:
identical registers. Induction over commit boundaries extends from one boundary to the
whole pass, since the state at boundary j is the initial state of segment j+1 and both
systems agree on it by the induction hypothesis. ∎

The proof is worth reading as an *engineering* statement: each hypothesis is enforced
by one mechanism — (H1) by using the same decoder, (H2) by the single-owner cache,
(H3) by the key discipline of §4, (H4) by type discipline. The 94 cells do not have to
*hunt* for divergence; they verify that the four mechanisms stay in place.

### 7.2 What "bit-exact" covers — and what it does not

Covered: all three ℤ³ coordinates per locate, at every commit boundary; all K2/K3
extension coordinates of Theorem 5; the per-chunk signatures themselves (comparable as
128-bit values for fast cell checking); anomaly counts (§5.6 policies) if the oracle
also produces them.

Not covered (and why that is fine): intermediate states *inside* a 512-message chunk —
they are not defined points of the parallel engine, and no cell should compare them.
If the 94 cells currently assert mid-chunk states, either (a) re-define their expected
values at the enclosing boundary, or (b) run the engine with commit granularity 1 in
debug mode — the algebra is granularity-agnostic (Theorem 4), so the *same binary*
serves both: `SIG_CHUNK=1` for cell mode, 512 for performance mode. That single flag
is the cheapest possible conformance story.

### 7.3 Mapping the 94 cells onto the theorem's hypotheses

| Cell class (representative mix) | Pins | Hypothesis |
|---|---|---|
| Single-type sweeps (`A`-only, `D`-only, …) | generator table rows (§2.2), decode offsets | H1 |
| Mixed `A→E→D` lifecycles, one id | chain order, `E` side/price resolution, clamps | H2 |
| `U` replaces (side flips, size grows/shrinks) | §5.6 policy 4, old-side delta | H2 |

Recommended cell arithmetic: 9 single-type sweeps + 9 pairwise-pair sweeps (A/D, A/E,
A/X, A/U, E/D, X/D, U/E, P-mix, Q-mix) + the taxonomy rows of §4.5/§7.5 ≈ 94 — i.e.
the existing suite is *exactly* the right shape to pin H1–H4 if each class asserts
state-hash equality at boundaries rather than intermediate values.

### 7.4 Integer discipline (the fine print that keeps Theorem 8 true)

- Accumulate K1 coordinates in `uint64_t` (wrapping is defined; `int64_t` overflow is
  UB and must never appear on either path). Cast to signed only at reporting time.
- The oracle MUST use the same u64 accumulators. A mixed i32/oracle-u64 pair diverges
  only on adversarial cells — the worst kind of bug: green on real data, red on the
  fuzzer, unexplainable in between.
- No FP in the fold — not even "temporary" double math for VWAP; VWAP is 2 × K1
  (Σpq, Σq) with one division at Ψ-time, and even that division belongs behind the
  reporting interface, not in the state.
- Shifts are on unsigned types; endianness conversions are `bswap` intrinsics, not
  pointer casts (alignment + strict-aliasing).

### 7.5 The augmentation list (cells 95–106, the adversarial residue)

1. **Up-print/down-print** (§4.1): `P(101.00), P(99.50)` → last = 99.50. Catches
   price-first comparison.
2. **Equal-price double print, both orders**: `P(x), P(x)` at distinct seqs — result x,
   and (with an extended payload tag) payload from the later.
3. **Same-timestamp double print**: two setters with identical ts, prices in both
   orders — result = the *wire-later* one. Catches every T2 anti-pattern.
4. **Sentinel-first partial chunk**: first chunk all-⊥, second chunk has a setter.
   Catches ε/π* disagreement (T3).
5. **Zero-price print**: `P(0)` mid-stream must *set* `last_px = 0` (D₀ path), not be
   mistaken for "no setter". Catches price-sentinel encodings.
6. **2⁶³-boundary positions**: wire positions crossing `INT64_MAX` (requires a >2⁶³
   message stream — synthesize by seeding the position counter near the boundary).
   Catches signed compares (T4).
7. **Partition invariance**: same stream folded at chunk sizes {1, 16, 64, 256, 512} —
   identical signatures and states. This is Theorem 4 as a cell.
8. **Memo == cold**: evaluate pass 1 cold, pass 2 memoized — identical. Prop 6.1 as a
   cell (must include a chunk whose entry states differ between passes).
9. **Chain-across-chunk**: `A` in chunk j, `E`+`D` in chunk j+1 — resolved against the
   persistent register, not a snapshot. Caches cross-boundary handling.
10. **`U` side flip**: BUY order replaced by SELL order, size change — both volume
    coordinates move, old side withdraws, new side adds.
11. **Over-cancel / over-execute clamps**: `X(q > rem)`, `E(q > rem)` — pinned to
    policy.
12. **All-⊥ 512-chunk followed by setter-only chunk** at a pass boundary — the r=977
    tail-chunk path (288 messages) exercised.

### 7.6 CI harness mechanics (cheap, deterministic, no float)

Compare **state hashes**, not states: `h = FNV-1a/xxh3 over (locate, b, a, p)` for all
touched locates at each boundary, in locate order (order the hash input canonically —
the hash is over a *set*, and the set must be serialized deterministically). The
oracle and the engine each emit a hash per boundary; cells compare hash vectors —
O(touched locates) memory, zero formatting, zero float. Golden hash vectors are
committed alongside the cells, so regressions pinpoint the exact boundary of first
divergence, which is the single most valuable debugging datum this design can emit.

## 8. Roofline: What the Math Buys and Where the Next Wall Is

All numbers use the stated platform: 2 cores / 4 vCPUs, Zen 5 @ 2.6 GHz, 48 KB L1D,
1 MB L2 per core, ≈165 GB/s memory bus, AVX-512 (8 × u64 lanes). Rates are per the
*whole 2-core socket* unless noted. Treat every figure as an engineering estimate to
be re-measured with the §8.5 protocol — the structure of the argument (which regime
bounds which claim) is the deliverable; the constants are honest midpoints.

### 8.1 The three regimes (and which claims live where)

| # | Regime | Working set | Binding resource | Est. rate (2 cores) | Supports |
|---|---|---|---|---|---|
| 1 | **Cold parse** (fresh stream, DRAM) | 15 MB per 500k msgs | CPU cycles (decode + probes), then bus | **≈ 0.8 – 2.5 B msg/s** (batched-ID resolution pushes toward 3–3.5B) | ingest throughput |
| 2 | **L2-resident token replay** | ≤ 1 MB (≈32k msgs/core) | L2 bandwidth + fold | **≈ 2 – 5 B msg/s** | bounded-window scans |
| 3 | **Memoized signature replay** | 31 KB per 500k msgs | ⊕ + table lookups (L1) | **≈ 20 – 60 B msg/s-equivalent**; conservatively ≥ 10–15B with lookup overhead | verdict re-evaluation, the 10B+ class of claims |

Derivations:

**Regime 1 — cold.** Bus ceiling: 165 GB/s ÷ ~30 B/msg ≈ 5.5 B msg/s absolute; but
the CPU gets there first: 2 cores × 2.6 GHz = 5.2 G cyc/s, so 1 B msg/s spends 5.2
cyc/msg. A tuned decoder (jump table + bswap) costs ~8–15 cyc/msg; a cache probe adds
~12–20 (L2 hit) — i.e. 0.5–1.0 B msg/s probe-bound if every message probes.
Batched-ID resolution (§5, grouping a chunk's ids before probing) and SMT overlap
(the two pipeline halves) move the realistic band to ~0.8–2.5 B. The fold itself is
noise here: 0.43–0.60 cyc/msg (§6.5) ≈ 10% of the per-message budget at 1 B msg/s.

**Regime 2 — L2 replay.** 32 B/token; Zen 5 L2 sustains ~32 B/cycle load — one core
streams ~2.6 G tokens/s if compute hides under the loads; with the fold at ~0.5
cyc/msg and combine/commit overheads, 1.5–2.5 B/core, ~2–5 B on the topology. This is
the regime for "scan the last hour repeatedly" workloads where tokens (not raw ITCH)
are the storage format.

**Regime 3 — memoized.** Per 500k-message pass: 977 table probes (~20–50 cyc each,
L1-resident table) + 976 ⊕ (~2 cyc) + per-locate Ψ ≈ **20–60 k cycles ≈ 8–23 µs**,
i.e. 22–60 B msg/s-equivalent if the pass is re-evaluated continuously; even
de-rating 3× for lookup misses and scheduling jitter, the 10–15B class is supported
with margin — *in this regime only*. This is precisely the regime the algebra
creates: 94-cell verdict re-evaluation, parameter sweeps over fixed streams, and
A/B policy comparisons are all regime-3 workloads.

### 8.2 What happened to "1,200 ms": an accounting note, stated honestly

The stated baseline — 1,200 ms per 500k-message pass — is 2.4 µs/message ≈ **6,240
cycles/message** at 2.6 GHz. A 3×3 integer matvec is ~20–30 cycles; even a naive
sequential state machine with a hash probe is ~50–150 cyc/msg. So the 1,200 ms is not
"500k matvecs"; it is a dependency-serialized pipeline paying full latency (not
throughput) per link, plus per-message bookkeeping of a full engine. The fold algebra
removes the dependency chain (Theorem 2), vectorizes the arithmetic (×8), and unlocks
the 2-core/SMT split (×~1.8) — but a substantial share of the resulting gain over
1,200 ms is recovered *engineering* (batching, branchless decode, ring handoff), not
algebra. The two contributions are separable and should be reported separately:
measure the old pipeline against the new one *with the fold stubbed out* to isolate
the algebra's share; expect the fold stage specifically to go 1,200 ms → ~0.1 ms
(§6.5), while the pass-level number lands wherever decode+probes put it (regime 1).

Likewise the "6.0B current / 15B target" figures cannot be reconciled with 1,200
ms/500k (0.42 M msg/s) without specifying which regime each number describes. The
roofline above is the reconciliation: nothing on this hardware cold-parses at 15B
(the bus alone forbids >5.5B), and nothing needs to — the *verdict* workload, which
is what the 10B+ headline is about, is a regime-3 workload and lands at ≥10B with
room.

### 8.3 The next wall (in order of arrival)

1. **Decode width** (regime 1): the jump-table decoder at 8–15 cyc/msg caps cold
   ingest near 0.7–1.3 B/core. SIMD decode (16 messages in parallel, type-driven
   lane dispatch — feasible because decode is field-extraction, no state) is the
   next 2–3×; it stays honest because (H1) is testable per lane.
2. **Cache probes** (regime 1): 1 probe/msg at 12–20 cyc is the co-equal wall.
   Batched per-ID resolution (§5.5's grouping variant) amortizes probes to ~0.3–0.5
   per message; beyond that, the memo table (§6.3) converts repeat traffic to L1
   lookups.
3. **L2 bandwidth** (regime 2): 32 B/token is generous; a 16 B packed token (seq:u48 +
   flags:u16, px:u32, db:i32, da:i32 with i64 widening at the combine) doubles
   regime-2 rates if scans are the product. The algebra does not change (the monoid
   is width-agnostic; widening is a homomorphism on K1).
4. **`⊕` throughput** (regime 3): 976 dependent-ish combines — vectorize the final
   reduction the same way as the chunk fold (it is the same monoid; 977 → tree of
   depth 10) if this ever shows; it won't before ~50B.

### 8.4 Latency (not just throughput)

Chunk-pipelined commit latency: decode+resolve of one chunk (~2–4 µs) + fold
(~0.1 µs) + ring handoff (~0.1 µs) + Ψ-commit (≈0.2–0.5 µs for a few hundred touched
locates) ⇒ **≈ 3–5 µs per 512-message boundary**, p99 dominated by rare long chains
and rehash events (pin rehash out of the hot path, §5.7). The verdict path (regime 3)
sees a full pass's signature ~1–2 µs after the last chunk lands.

### 8.5 Benchmark protocol (so the numbers stop being contested)

Report four numbers per configuration, all on the CI runner, all with
`taskset`/affinity pinned and SMT state logged: (1) cold-parse msg/s (unique stream,
page-cached-in, measured after warmup of code paths only); (2) regime-2 msg/s
(repeated scan of a 32k-token window); (3) regime-3 replay msg/s-equivalents
(100 re-evaluations of a 500k pass, memoized); (4) fold-stage cycles/msg isolated
(fold stub vs fold live, subtract). Each with p50/p99 per-512-chunk latency. Publish
`L` (max chain length, §5.4) and probe counts per 1k messages alongside — they are
the two variables that move regimes 1–2, and they make results reproducible across
machines.

## Appendix A. Proofs for the Extension Algebra and the Monoid Laws

### A.1 Lemma 2 in full — `(Tg, ⊔)` is a commutative idempotent monoid

Work with the extended tag space
`Tg := {⊥} ∪ (ℤ × K)` where `K` is a set of keys equipped with a **strict total order**
`<` (in the engine: `K = ℕ₊` with the usual order, or `ℕ₊²` lexicographic for
`(timestamp, wire_position)` — both are strictly totally ordered and key-injective by
construction). Define:

```
  ⊥ ⊔ τ = τ ⊔ ⊥ = τ                       (⊥ is a unit)
  (π, k) ⊔ (π′, k′) = the operand with the < -maximal key
```

**Claim.** `⊔` is associative, commutative, idempotent, with identity `⊥`.

*Proof.*

*Commutativity*: symmetric in the operands by inspection (the definition only refers to
which key is maximal, not to operand position).

*Identity*: the first line of the definition, plus the fact that `⊔` of a single
non-⊥ element with anything is decided among non-⊥ keys ⊇ that element.

*Idempotence*: `(π,k) ⊔ (π,k)` — both keys equal, the maximal key is `k`, and the
operand carrying it is the same tag on both sides; the result is `(π,k)`. Formally,
when keys are equal the two operands are *identical elements of Tg* (the key is
injective over tags in a given evaluation — see the remark below), so "the operand
with the maximal key" is unambiguous.

*Associativity*: let `x, y, z ∈ Tg`. If any of them is `⊥`, associativity reduces to
the two-operand law on the remainder (four trivial cases). Otherwise all three are
tags `(πₓ,kₓ), (π_y,k_y), (π_z,k_z)`. Since `<` is a strict total order on keys, the
set `{kₓ, k_y, k_z}` has a unique maximum `k*` (uniqueness: strict total orders are
antisymmetric; two distinct keys cannot both be maximal). Then:

```
  (x ⊔ y) ⊔ z = (tag with key max(kₓ,k_y)) ⊔ z = tag with key max(max(kₓ,k_y), k_z)
             = tag with key max(kₓ, k_y, k_z) = k*
  x ⊔ (y ⊔ z) = x ⊔ (tag with key max(k_y,k_z)) = tag with key max(kₓ, max(k_y,k_z))
             = tag with key k*
```

and the *payload* carried is in both cases the payload of the unique operand with key
`k*`. Hence `(x⊔y)⊔z = x⊔(y⊔z)`. ∎

*Remark (why Lemma 2 was stated for distinct keys in the main text).* If two *distinct*
tags share a key (a key collision), "the operand with the maximal key" is ambiguous —
`⊔` becomes a partial/implementation-defined operation, and associativity can fail
precisely because different association orders may pick different colliding operands.
This is not a defect of the construction; it is the T2 hazard of §4.3, and the fix is
to make keys injective by construction (`(timestamp, wire_position)` lexicographic),
which restores the strict-total-order hypothesis above. The engine's canonical key —
1-based wire position — is injective by definition, so the lemma applies verbatim.

### A.2 The monoid laws for `⊕` (Theorem 2(iii))

`𝒜₅.₀ = (ℤ² × Tg, ⊕)` with `(x, τ) ⊕ (x′, τ′) = (x + x′, τ ⊔ τ′)`.

*Proof of the laws.* `(ℤ², +)` is an abelian group, hence a commutative monoid.
`(Tg, ⊔)` is a commutative monoid (A.1). The componentwise product of two monoids is a
monoid with identity `(0, 0, ⊥)` (pair of identities), and it is commutative when both
factors are. Explicitly, for `a=(x,τ), b=(x′,τ′), c=(x″,τ″)`:

```
  (a ⊕ b) ⊕ c = ((x+x′)+x″, (τ⊔τ′)⊔τ″) = (x+(x′+x″), τ⊔(τ′⊔τ″)) = a ⊕ (b ⊕ c)
```

using associativity of `+` and of `⊔`; commutativity and identity similarly, component
by component. The same argument shows any finite product of commutative monoids is
commutative — used by Theorem 5. ∎

### A.3 Theorem 5 in full — coordinate monoids

**Setup.** State `X = ∏_c X_c`. Each message's operator is `⊗_c f_c^m` where `f_c^m`
acts on coordinate c only (coordinate-wise action: no generator's effect on c reads
another coordinate). Each coordinate's operator family is entirely of class K1, K2, or
K3 (§3.6 table).

**Claim.** For each class, the composite over any batch is the fold of a *commutative*
monoid, with the stated operation; hence the batch composite over `X` is the product
fold, which is commutative; chunking and memoization (Theorems 2(i), 4, Prop 6.1
arguments) carry over verbatim.

*Proof, class by class.*

**(K1) Accumulation** `x ↦ x + β(m)` (β a function of message fields only). The
composite over a batch B is `x ↦ x + Σ_{m∈B} β(m)` — a fold in `(ℤ, +)`, or in
`(ℤ/2⁶⁴, +)` for the machine representation (an abelian group; identical argument).
Commutative and associative because `+` is. Note the proof nowhere requires β to be
small, positive, or monotone — only that it depends on the message, not on the state.

**(K2) Last-writer** — each message either acts as the identity on c (non-assignment)
or as `x ↦ π(m)` (assignment). Claim: the composite over B is `x ↦ π(m*)` where `m*`
is the assignment with the ⊔-maximal key, or the identity if B contains no
assignment. Proof by induction on |B|. Base |B| = 0: identity. Step: let B = B′ ∪ {m}
(m last in some processing order — *any* order, since we are proving
order-independence). By the inductive hypothesis the composite over B′ is assignment
by `m*′` (or identity). If m is a non-assignment, the composite over B is the
composite over B′: done. If m is an assignment, the final operation applied is m's
assignment (whenever it is applied, it overwrites whatever the rest of B did), so the
composite is assignment by m *if we process m last* — but for a different processing
order, the same argument shows the composite is assignment by whichever assignment is
applied **last**, and "applied last" is well-defined only in terms of the evaluation
order. This is exactly where the key discipline enters: define the batch's result as
assignment by the **key-maximal** assignment `m*`. Under strict-monotone injective
keys (Theorem 6 hypotheses), `m*` is the stream-last assignment, and a direct
induction on stream order (not processing order) — where "later stream message's
assignment always overwrites earlier" — gives the result. The monoid is `(Tg, ⊔)`
(A.1): non-assignments contribute `⊥`, assignments contribute `(π(m), key(m))`, and
⊔ selects the key-maximal payload. ∎ (This is Corollary 1.1(b), abstracted from the
`D₀` structure to arbitrary assignment coordinates — the reason Theorem 5 needs no
matrix algebra at all.)

**(K3) Extremum** `x ↦ max(x, π(m))` (or min). The composite over B is
`x ↦ max(x, max_{m∈B} π(m))` — a fold in `(ℤ ∪ {−∞}, max)`, commutative, associative,
idempotent. Note K3 does not need keys: max is already order-free. (K3 with sentinels:
the identity is −∞; the "unset" state is exactly the identity element — this is why
the K3 sentinel may live in the *value*, unlike K2 where it must live in the *key*.)

**Product.** The composite over `X` of a batch is `⊗_c (composite over c)` because
coordinate-wise operators over disjoint coordinates commute pairwise (each `f_c`
acting on `∏_c X_c` is `f_c ⊗ (∏_{c′≠c} id)`; the exchange law is a two-line
computation on products). Each factor's composite is the fold of a commutative monoid
(K1–K3 above), so the product is the fold of a product of commutative monoids, which
is commutative (A.2). Chunk-homomorphism and memoization arguments then replicate
Theorem 2(i), Theorem 4, and Prop 6.1 word-for-word with `⊕` replaced by the product
operation. ∎

### A.4 Theorem 7 in full — the register-file argument in complete generality

Formally: let `IDs` be a countable set and `R = V ∪ {ABSENT}` a value domain. The
cache state space is `O = R^IDs` (all functions from ids to values; `ABSENT` is the
default). For each id α define the *coordinate projections*
`π_α : O → R` and, for `v ∈ R`, the *update* `U(α, v) : O → O` with
`π_β(U(α, v)(o)) = v` if β = α, else `π_β(o)`.

**Exchange law.** `U(α, v) ∘ U(β, w) = U(β, w) ∘ U(α, v)` for α ≠ β, since both
sides map coordinate α to v, coordinate β to w, and fix every other coordinate.

**Theorem (general form of 7(i)–(ii)).** Let `σ` be any finite sequence of updates.
Then `fold(σ) = ∏_α fold(σ|_α)` — i.e. the final cache is the pointwise combination of
the per-id subsequence folds — and `fold(σ) = fold(σ′)` whenever `σ′` is a
rearrangement of σ that preserves each `σ|_α` as a sequence.

*Proof.* First part: induction on |σ|. Empty case trivial. Step: σ = τ · U(α, v)
(append at end). Then `fold(σ) = U(α, v)(fold(τ))`, and by the exchange law
`U(α, v)` commutes with every update in τ acting on ids ≠ α; updates acting on α are
exactly the tail of `σ|_α`, so `fold(σ)|_α = fold(σ|_α)` (per-id sequences fold
independently) and `fold(σ)|_β = fold(τ)|_β = fold(σ|_β)` for β ≠ α. Second part:
rearrangement-invariance follows because any chain-order-preserving σ′ can be
transformed into σ by repeatedly swapping *adjacent* updates with distinct ids, and
each swap leaves `fold` fixed by the exchange law (a standard adjacent-transposition
argument: the symmetric group on positions is generated by adjacent transpositions,
and only swaps of distinct-id pairs are needed to sort either sequence into the
canonical interleaving "all of α₁'s updates, then α₂'s, …" — which both σ and σ′
reach, since each preserves chain order). ∎

Parts (iii) and (iv) of Theorem 7 are then read off: reads at a message are
projections of the prefix fold (iii), and the longest dependency chain is bounded by
the longest per-id subsequence (iv).

### A.5 Theorem 8 — assembly detail

The main text (§7.1) reduces Theorem 8 to: token-content equality (H1+H2, via
Theorem 7) + signature-map equality (Theorem 2(ii)) + selection determinism
(Theorem 6) + representation equality (H4). One step deserves explicit care: **the
ℤ → ℤ/2⁶⁴ transfer for K1**. Theorem 2's volume argument used commutativity and
associativity of `+` in ℤ; `(ℤ/2⁶⁴, +)` has both properties (it is an abelian group),
so every equation in the proof — which are all identities between sums of `Bᵢ`
components — maps homomorphically under `ℤ → ℤ/2⁶⁴` (the natural projection is a ring
homomorphism). Equality in ℤ implies equality in the quotient; hence the parallel
reduction's K1 result equals the oracle's K1 result *in ℤ/2⁶⁴*, i.e. identical u64
registers. (The converse fails — two different integer sums may agree mod 2⁶⁴ — but
only the forward direction is needed, and it is exactly why the machine
representation may wrap without breaking conformance, provided the oracle wraps
identically: both sides then compute the same quotient element.) The K2/K3 factors
involve no arithmetic, only order comparisons, which are exact in the machine. ∎

```
  +0      1     Message Type (one of 'A','F','E','C','X','D','U','P','Q')
  +1      2     Stock Locate (u16 BE)      ← the ℓ of every S_ℓ
  +3      2     Tracking Number (u16 BE)   ← not state-relevant
  +5      6     Timestamp (u48 BE, ns since midnight)  ← T2 hazard if used as ⊔ key
```

Arithmetic cross-checks that the lengths below are field-sum-exact:
`D = 11+8 = 19`, `X = 11+8+4 = 23`, `E = 11+8+4+8 = 31`, `A = 11+8+1+4+8+4 = 36`,
`F = A+4 = 40`, `C = 11+8+4+8+1+4 = 36`, `U = 11+8+8+4+4 = 35`,
`Q = 11+8+8+4+8+1 = 40`. All big-endian; every multi-byte load needs `bswap`.

### B.2 Per-type field lists and the generator each induces

**(A) Add Order, no MPID — 36 B.** `OrderRef u64 | Buy/Sell 'B'/'S' | Shares u32 |
Stock 8×char | Price u32 (10⁻⁴)`.
Generator: `A = I₃`, `B = ν(side, +shares)`; cache INSERT. Signature:
`(±shares → db/da, ⊥)`.

**(F) Add Order with MPID — 40 B.** Same as A + `MPID 4×char`. Generator identical to
A (attribution is not state).

**(E) Order Executed — 31 B.** `OrderRef u64 | Executed Shares u32 | Match Number u64`.
Generator: `A = D₀`, `B = (ν(side, −executed), px_resting)` under `E_SETS_LAST =
order_px`; else pure translation. Cache: READ (side, px, rem); `rem −= executed`
(clamped per §5.6). *Note the wire message carries no price — the price is cache
state; this is the canonical example of §5.1.*

**(C) Order Executed With Price — 36 B.** `OrderRef u64 | Executed Shares u32 |
Match u64 | Printable 'Y'/'N' | Execution Price u32`.
Generator: printable ⇒ `A = D₀, B = (ν(side, −executed), π_exec)`;
non-printable ⇒ `A = I₃, B = ν(side, −executed)`. Cache: READ (side, rem); update.

**(X) Order Cancel — 23 B.** `OrderRef u64 | Cancelled Shares u32`.
Generator: `A = I₃`, `B = ν(side, −min(cancelled, rem))`. Cache: READ (side, rem);
`rem −= cancelled` (clamped, never below 0).

**(D) Order Delete — 19 B.** `OrderRef u64`.
Generator: `A = I₃`, `B = ν(side, −rem)`. Cache: READ (side, rem); ERASE.

**(U) Order Replace — 35 B.** `Original Ref u64 | New Ref u64 | Shares u32 |
Price u32`. (No stock symbol — it inherits the original order's.)
Generator: `A = I₃`, `B = ν(side_old, shares_new − rem_old)`. Cache: READ old
(side, rem); ERASE old; INSERT new with the message's fields. §5.6 policy 4.

**(P) Trade, non-cross — 43/44 B †.** `OrderRef u64 | Buy/Sell | Shares u32 |
Stock 8×char | Price u32 | Match u64`.
Generator: `A = D₀`, `B = (0, 0, π)` — non-displayable: no volume effect. No cache
activity. (OrderRef may be 0 for non-displayable prints; irrelevant to the fold.)

**(Q) Cross Trade — 40 B.** `Shares u64 | Stock 8×char | Cross Price u32 |
Match u64 | Cross Type char`.
Generator (default `Q_VOLUME_POLICY = print_only`): `A = D₀`, `B = (0, 0, π)`.

**† The `P` length pin.** The field list sums to 44 (11 + 8 + 1 + 4 + 8 + 4 + 8),
while several circulating reference tables print 43 for `P` (and 36 for `A`, which
does check out). The discrepancy is exactly one byte and exactly the kind of thing
that must never be resolved by consensus: **pin every message length and field offset
from the official Nasdaq PDF your conformance cells certify against, and assert
lengths at decode time** (checklist step 1). The generator algebra is unaffected by
the pin's outcome — a one-byte shift moves a field offset, not a semantic.

### B.3 Derived quantities (decode-time)

- `side ∈ {B, S}` → the ν-selector: branchless via `e[0]=='B'` as a 0/1 mask indexing
  `(db, da)`.
- Prices are u32 with implied 10⁻⁴; the fold keeps them as raw u32 (integer ticks) —
  *never* convert to float (H4). Any display scaling happens at the reporting edge.
- `px = 0` is a legal wire value (and appears in cross placeholders): it is a real
  *assignment to zero* for `P`/`Q` with π = 0, which the sentinel-in-seq encoding
  handles correctly and the sentinel-in-price encoding does not (T3, cell 95-5).
- `seq` for the token is the 1-based wire position of the message in the pass — NOT
  the header timestamp (T2). The timestamp remains available as payload for
  extended tags if verdicts need it, but it must not be a comparison key.

## Appendix C. Why an Exact Composition LUT Is Impossible

The second hypothesis in the problem statement — "a pre-computed generator algebra
over ℤ³, looked up for 256/512-message batches" — deserves a precise answer, because
the failure is instructive and the substitute is better than the ask.

**C.1 The signature space is genuinely infinite (cardinality).** Restrict to
1-message batches of type `A` on the BUY side: their signatures are
`(q, 0, ⊥)` for every encodable share count `q ∈ [0, 2³²)`. So already the
1-message corner of any exact composition table has ≥ 2³² entries × 32 B ≈ 137 GB —
larger than everything the memory bus can reach in a pass. Two-message batches reach
`Δb` sums spanning ≥ 2⁶⁴ values; price setters add ≥ 2³⁰ prices × 2⁶⁴ keys. The map
"batch → (A_net, B_net)" has an image of size ≥ 2⁶⁴ on the translation component
alone; any exact table is at least that big. (The problem's own formula
`B_net = Σᵢ (Πⱼ Aⱼ) Bᵢ` already shows it: `B_net` ranges over all of ℤ³-weighted
sums — there is no finite quotient to tabulate.)

**C.2 Information-theoretic statement.** A 512-message batch contains ≥ 512 ×
(field entropy) bits; its signature compresses exactly the state-relevant part to
192 bits (Δb, Δa, π*, s*). Any data structure that answers "batch → signature"
exactly is a lossless encoding of those 192 bits per chunk, keyed by the batch. The
signature *is* already the minimal such encoding — 4 machine words, no collisions,
no quantization. A table cannot beat the value it stores: the best exact "lookup" is
a content-addressed store of signatures, i.e. **memoization** (§6.3), populated by
the actual stream distribution rather than pre-enumerated over an infinite domain.

**C.3 Compute beats lookup even where lookup exists.** For a chunk whose entry is
memoized, the hit path costs hash (~5–10 cyc) + probe (~4–20 cyc, L1/L2) + seqlock
check — call it 15–30 cycles — versus a *miss* that falls back to the fold at ~0.5
cyc/msg × 512 ≈ 260 cycles. The fold is so far under the lookup cost that the memo
table is only worth building for **replay** (regime 3), where it eliminates decode +
probes (the real costs), not for first-pass composition, where it would add traffic
to save arithmetic that no longer exists. Precomputation of a *finite* generator
table does exist in the weak and sufficient sense: the 9-entry type → template table
of §2.2, instantiated by message fields — that is the "generator algebra", and its
per-message cost is 5 ALU ops.

**C.4 Why quantized/approximate LUTs are disqualified outright.** Any table that
quantizes (Δb, Δa) buckets or price keys produces results that are *close* but not
*equal* to the sequential oracle — and the 94-cell contract (and Theorem 8) is
bit-equality, not ε-equality. A 10⁻⁹ relative error in a volume coordinate is a
failed cell, a failed audit, and a genuinely different book. There is no regime in
which approximate composition is preferable here: the exact algebra is cheaper than
any table that could serve it.

**Bottom line:** the requested "pre-computed generator algebra" exists — it is the
signature algebra itself, with the 9-template table as its finite presentation, ⊕ as
its (O(1), exact) composition law, and the memo table as its content-addressed cache
for the replay workloads where lookup genuinely wins.
